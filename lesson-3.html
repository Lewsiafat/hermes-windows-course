Step 1 / 6 · context 管理：聊太久會變慢

~7 分鐘

為什麼會變慢

跟 hermes 講話，它會把目前對話的所有訊息都送進 LLM。對話越長 → context 越大 → LLM 處理越慢、回答越貴、注意力越分散。這叫 context window 飽和。

具體症狀：

  • 同一個 bot 越聊越慢回
  • 有時 bot 忘記你前面講過的事
  • OpenRouter free 模型直接 rate limit 或丟錯

解法：切話題就 /new

規則就一句：你要問的東西跟前面沒關係 → /new。

實作：試一次 /new

  1. 打開手機 Telegram，找你 Lesson 2 接好的 bot
  2. 傳：幫我算 12345 * 6789
  3. bot 回答後，傳 /new
  4. 看到 bot 回確認訊息（類似「✓ 開新對話」、「session reset」等字眼）
  5. 傳 what was my last question? → bot 應該說「沒看到上一題」或類似（因為 context 已清）

✓ 知道何時 /new + 確認 bot 清空 context → checkpoint 1 完成。

還有 /title /resume /sessions 配合 /new 用

Lesson 2 Step 7 已有完整 cheatsheet。簡單講：

  • /title 中翻英練習 — 在 /new 開新對話之前幫目前 session 取名，這樣之後可找回
  • /sessions — 列所有取過名的 session
  • /resume 中翻英練習 — 跳回那個 session 繼續聊

實務節奏：寫一個專案 → /title 專案名 → 聊完 → /new。下次想接著做 → /resume 專案名。

Step 2 / 6 · 常用 / 指令（skills 相關）

~5 分鐘

Lesson 2 Step 7 的 cheatsheet 已經涵蓋 /new /model /help 這些。Lesson 3 新增兩組 skills 專用指令：

指令說明
/skillsSkills Hub 命令群（不是「列清單」指令）。打進去會看到子命令選單：browse / search / install / inspect / list / check / update / audit / uninstall / publish / snapshot / tap……
/skills list真正列出已安裝 skills（bundled 內建 + 你自己寫的）。輸出多會分頁，按 continue / n 看下一頁。
/skills list --source local只列你自己寫的本地 skills（過濾掉一大串內建 skill 才好找）。Step 4 寫完 daily-journal 後用這條最快驗證。
/<skill-name>直接呼叫某個 skill。例如 /plan 呼叫內建 plan skill；Step 4 寫完 daily-journal 就能打 /daily-journal。
/<skill-name> 額外參數傳參數給 skill。例：/plan 設計一個 cron 排程器 → 把後面字串當輸入。

實作：跑一次 /skills list

  1. 在你的 hermes CLI 或 Telegram bot 傳 /skills，先看一下 Skills Hub 命令選單長怎樣（之後 Step 4 收尾會用到 install、inspect）
  2. 傳 /skills list 看完整清單。應該看到一大堆 bundled skill：plan、excalidraw、architecture-diagram、ascii-art……
  3. 傳 /plan 寫一份本週讀書計畫 → bot 套用 plan skill 的指令幫你寫出 markdown 計畫

✓ 看到 /skills list 列出清單 → checkpoint 2 完成。

📚 為什麼 skill 自動變成 slash command

每個 skill 在 ~/.hermes/skills/<category>/<name>/SKILL.md 的 frontmatter 都有 name: 欄位。hermes 啟動時掃描整個 skills 目錄、為每個 name 註冊一個對應的 top-level slash command。所以 Step 4 寫完 name: daily-journal 的 SKILL.md，重啟後就會自動有 /daily-journal 可用——CLI 跟 Telegram 都認得。

呼叫時 hermes 會印 ⚡ Loading skill: daily-journal，並把 SKILL.md 整份內容注入 LLM context。你會在輸出開頭看到 [IMPORTANT: The user has invoked the "daily-journal" skill...] 的提示——那是 hermes 自己加的引導，讓 LLM 嚴格照 SKILL.md 的 Procedure 走。

Vibe Coding 實戰 · superpowers + SDD

用 hermes-agent + superpowers skills 跑完「brainstorm → plan → implement → review」完整一輪，90 分鐘

前言

前言 · 什麼是 Vibe Coding + Superpowers？

~5 分鐘

Vibe Coding 是一種你主導方向、AI 執行實作的開發方式。但「叫 AI 寫 code」跟「AI 寫出好 code」中間差很遠——大多數人第一次嘗試都遇到同樣的問題：AI 跳過設計直接亂寫、沒有測試、改到一半偏離需求。

★ 解法：Superpowers

Superpowers 是一套給 coding agent 用的完整開發方法論，打包成一組 skills。它不是一個「能讓 AI 跑程式碼」的工具——hermes 本身就有 tool-use（shell、檔案讀寫等）。Superpowers 的價值是：自動在正確的時機觸發正確的工作流程。

裝好之後，你只要說「幫我做一個 X」，superpowers 就會自動：

  1. Brainstorming——先問你需求、釐清設計，不會直接跳進寫 code
  2. Writing Plans——把實作拆成一個個 2~5 分鐘的小任務，附完整驗證步驟
  3. Subagent-Driven Development (SDD)——每個任務派一個子 agent 執行，完成後自動兩階段 review（規格合規 + 程式碼品質）
  4. Test-Driven Development——強制 RED-GREEN-REFACTOR 循環，先寫測試再寫實作
  5. Code Review——對照計畫逐項檢查，critical issue 會擋住進度

這些 skills 自動觸發，不需要你手動呼叫——這是 superpowers 的核心設計。

今天會做什麼

  1. Step 1：在 hermes 裝好 superpowers skills
  2. Step 2：走一次 brainstorming 流程——體驗「不直接寫 code」的感覺
  3. Step 3：讓 superpowers 寫計畫 + SDD 自動實作
  4. Step 4：Code review + 迭代修正
  5. Step 5：收尾——git worktree 管理、merge、下次預告

4 個 checkpoints

  1. Superpowers skills 裝好、/skills 列表看得到
  2. Brainstorming 跑完、你核可了一份設計
  3. SDD 自動實作完成、測試通過
  4. Code review 通過、git 留下乾淨紀錄
前置條件

這堂課假設你已完成 Lesson 1（安裝 hermes），hermes 可以在你的機器上正常對話。不需要做過 Lesson 2–5。

本堂是實作課，hermes 在課堂中會幫你寫程式——需要付費 model（/model anthropic:claude-sonnet-4 或同等）。SDD 流程會派子 agent，免費 model 幾乎無法完成。

你的 WSL Ubuntu 需要有 git（用來做 worktree）。大部分 Ubuntu 預裝了，確認一下：git --version。

Step 1 / 5 · 安裝 superpowers skills

~10 分鐘

Superpowers 是一組遵循 agentskills.io 開放標準的 skills。hermes-agent 內建了 Skills Hub，可以從多個來源搜尋、安裝 skills。安裝方式有兩種——推薦用方法 A（一次裝完所有 superpowers skills）。

方法 A：用 git clone 一次裝完（推薦）

Superpowers 的所有 skills 都在同一個 GitHub repo 裡。最直接的方式是把整個 skills/ 資料夾 clone 到 hermes 的 skills 目錄：

git clone https://github.com/obra/superpowers.git ~/.hermes/skills/superpowers

這樣 hermes 會自動掃描到裡面每個 skills/*/SKILL.md，包含：

  • using-superpowers——核心 bootstrap，讓 skills 自動觸發
  • brainstorming——需求釐清 + 設計
  • writing-plans——把設計拆成可執行任務
  • executing-plans——照計畫一步步實作
  • subagent-driven-development——派子 agent + 兩階段 review
  • test-driven-development——TDD 循環
  • requesting-code-review / receiving-code-review——code review 流程
  • using-git-worktrees——隔離工作環境
  • finishing-a-development-branch——收尾 merge/PR
  • systematic-debugging——系統化除錯
  • verification-before-completion——完成前驗證
  • dispatching-parallel-agents——平行派發子 agent
  • writing-skills——教你寫自己的 skills

方法 B：用 hermes skills hub 逐一安裝

如果 hub 上找得到 superpowers 的個別 skill，可以用 hermes 內建的 Skills Hub：

hermes skills search superpowers
hermes skills install <identifier>

或在 hermes 對話中用 slash command：

/skills search superpowers
/skills install <identifier>

（如果 hub 沒有，就用方法 A。）

驗證安裝

在 hermes TUI 輸入：

/skills

確認列表裡看到 using-superpowers、brainstorming、writing-plans 等 skills。如果有看到，代表 hermes 已經掃描到它們了。

✓ /skills 列表看到 superpowers 的 skills → checkpoint 1 完成。

我卡住了

/skills 沒列出 superpowers

  1. 確認目錄結構對不對：ls ~/.hermes/skills/superpowers/skills/ 應該看到 brainstorming/、using-superpowers/ 等資料夾
  2. hermes 掃描的是 ~/.hermes/skills/ 下所有包含 SKILL.md 的子目錄（遞迴掃描），所以 clone 進去的 repo 結構是 ~/.hermes/skills/superpowers/skills/brainstorming/SKILL.md——hermes 會找到它
  3. 傳 /new 重開對話，讓 hermes 重新掃描 skills

另一個方法：用 external_dirs 設定

如果你不想把 superpowers clone 到 ~/.hermes/skills/ 裡面，可以 clone 到任何地方，然後在 hermes 的 config.yaml 加上 skills.external_dirs：

hermes config set skills.external_dirs '["~/superpowers/skills"]'

這讓 hermes 在掃描 skills 時也搜尋你指定的外部目錄。

git clone 失敗

確認 WSL 有裝 git、能連上 GitHub：git --version 跟 ping github.com。如果是公司網路問題，可以在有網路的地方先 clone 再搬過去。

Step 2 / 5 · Brainstorming——先設計再動手

~15 分鐘（★ 這是整堂最重要的一步）

裝好 superpowers 之後，最大的改變是：hermes 不再接到需求就直接寫 code。using-superpowers 這個 bootstrap skill 會在每次對話開始時自動載入，讓 hermes 在動手前先檢查「有沒有適用的 skill」。當你說「幫我做一個 X」，它會自動觸發 brainstorming skill。

1. 說出你想做的東西

挑一個你真的想要的小工具（不要太大，30~60 分鐘的實作量）。在 hermes TUI 直接說：

幫我做一個 [描述你的工具，例如：CLI 工具，讀取一個 CSV 檔案，算出每欄的平均值和最大值，輸出成一份 markdown 報告]
第一次建議選「你現在就知道輸入長什麼樣」的工具。能說清楚「輸入是 X，我要 Y」，成功率最高。

2. 體驗 brainstorming 流程

superpowers 的 brainstorming skill 會引導 hermes 做這些事：

  • 提問——它會問你需求上模糊的地方（「輸入如果有空行怎麼辦？」「要支援哪些資料型態？」）
  • 探索替代方案——「用 pandas 還是純 Python？」「要不要支援 Excel？」
  • 分段呈現設計——不會一次丟一大塊，而是把設計拆成「短到你真的會看完」的段落，一段一段確認

你的工作就是看它的問題、給明確答案。不確定的地方講「你決定」也行——重點是走完這個流程，讓需求變清楚。

3. 核可設計

brainstorming 結束時，hermes 會呈現一份完整的設計摘要。你覺得 OK 就說「好，按這個做」。要改就說「[哪裡] 改成 [什麼]」。

✓ brainstorming 完成、你核可了設計 → checkpoint 2 完成。

我卡住了

hermes 沒跑 brainstorming、直接開始寫 code

代表 using-superpowers bootstrap 沒有成功載入。確認方式：

  1. 傳 /new 重開對話——superpowers 的 bootstrap 是在對話開始時觸發的
  2. 再次確認 /skills 列表有 using-superpowers
  3. 如果用免費 model，它可能推理力不足以遵循 skill 指令——請切換到付費 model（/model anthropic:claude-sonnet-4）

brainstorming 太冗長 / 問太多問題

直接說：「設計差不多了，我覺得可以開始了。」superpowers 的 skill 尊重你的指示——你說可以就可以。

我想手動觸發 brainstorming

直接在對話中打：

/brainstorming

這會載入 brainstorming skill 的完整指引。

Step 3 / 5 · 寫計畫 + SDD 自動實作

~30 分鐘（★ 主場——看 superpowers 自動跑）

設計核可後，superpowers 會自動進入下一個 skill：writing-plans，然後 subagent-driven-development。這一步你主要是看它跑 + 在關鍵節點確認。

1. Git Worktree 隔離環境

superpowers 的 using-git-worktrees skill 會先建立一個 git worktree——在 feature branch 上工作，不會弄髒你的 main。如果你的專案還沒有 git repo，hermes 會先 git init。

好，開始實作。

你只要這樣說，superpowers 就會自動走下去。

2. Writing Plans（自動觸發）

writing-plans skill 會把設計拆成：

  • 每個任務 2~5 分鐘可完成
  • 每個任務附上確切的檔案路徑、完整程式碼、驗證步驟
  • 計畫會呈現給你看——確認後才開始實作

3. SDD 自動實作（自動觸發）

superpowers 的核心 subagent-driven-development skill 會：

  1. 對每個任務派一個子 agent——子 agent 只看到這個任務的指令，不會被其他任務污染
  2. 子 agent 寫 code + 寫測試——遵循 TDD：先寫一個會 fail 的測試（RED），再寫實作讓它通過（GREEN），最後重構（REFACTOR）
  3. 兩階段自動 review——第一階段檢查「有沒有按規格做」，第二階段檢查「程式碼品質」
  4. 繼續下一個任務——直到計畫裡所有任務都完成

這個過程可能需要 10~30 分鐘，取決於專案大小。hermes 可以自主跑一段時間不偏離計畫——這就是 superpowers 的設計目標。

4. 看輸出、確認測試通過

SDD 跑完後，hermes 會報告結果。確認：

  • 所有測試都通過（GREEN）
  • 功能符合你在 Step 2 核可的設計

✓ SDD 自動實作完成、測試通過 → checkpoint 3 完成。

★ 實作過程提醒
  • 別急著打斷：SDD 設計上就是讓 agent 自主跑完一連串任務。中途打斷反而會讓上下文混亂
  • 有 error 不等於失敗：TDD 的 RED 階段本來就會有 test failure——那是正常的。看到「test failed」不用緊張，等它自己修到 GREEN
  • 真的卡住才介入：如果同一個 error 反覆出現超過 3 次，才需要你手動說「試試 [另一個方向]」
我卡住了

hermes 沒有自動派子 agent

SDD 需要 model 支援子 agent 功能。確認你用的是付費 model（/model anthropic:claude-sonnet-4）。免費 model 不支援子 agent dispatch。

子 agent 一直 fail

先看 review 結果——如果是「規格不符」，可能是 brainstorming 階段的設計不夠清楚。直接說：「這個任務的需求其實是 [更清楚的描述]，重跑這個任務。」

跑太久 / 無限迴圈

在 hermes TUI 按 Ctrl+C 中斷目前工作，然後跟 hermes 說：「跳過這個任務，先做下一個。」superpowers 的 plan 允許你調整任務順序。

Step 4 / 5 · Code Review + 迭代修正

~15 分鐘

SDD 跑完不代表結束。superpowers 的 requesting-code-review skill 會自動啟動一輪最終 code review——對照原始計畫逐項檢查。

1. 自動 Code Review

superpowers 的 review 機制會按嚴重程度分級：

  • Critical——會擋住進度，必須修
  • Major——強烈建議修
  • Minor——改了更好，不改也能 ship

如果有 Critical issue，hermes 會自動修正然後重新 review。

2. 你自己也看一遍

AI 的 review 不能取代你的判斷。花 5 分鐘看一下：

  • 主要流程你能用自己的話說明嗎？
  • 有沒有多做了你不需要的東西？
  • 輸出格式是你要的嗎？

有問題直接說：

[描述問題]，幫我修。

3. 迭代到滿意

要改需求？先回去改設計：

需求變更：[描述新需求]。幫我更新計畫再重新實作受影響的部分。

superpowers 會重走 writing-plans → SDD 的流程，但只針對改動的部分。

4. verification-before-completion

superpowers 有一個 verification-before-completion skill——在宣告完成之前，它會自動做一輪最終驗證：跑所有測試、確認沒有遺漏。這是品質的最後一道防線。

✓ code review 通過、你確認滿意 → checkpoint 4 完成。

我卡住了

review 一直有 Critical issue 改不完

可能是原始設計太複雜。簡化需求：「先不做 [某功能]，其他照舊。」做完核心功能再迭代加功能。

不確定某段 code 在幹嘛

直接問：「[這段 code] 在做什麼，用一句話說。」你能解釋主要流程，才算真的擁有這段 code。

Step 5 / 5 · 收尾——merge + 下次預告

~10 分鐘

恭喜，4 個 checkpoints 全部完成：

  1. ✓ Superpowers skills 裝好、/skills 列表看得到
  2. ✓ Brainstorming 跑完、你核可了一份設計
  3. ✓ SDD 自動實作完成、測試通過
  4. ✓ Code review 通過、git 留下乾淨紀錄

Finishing：merge 或 PR

superpowers 的 finishing-a-development-branch skill 會在最後呈現三個選項：

  1. Merge——直接合併 feature branch 到 main
  2. PR——開一個 Pull Request（如果你有 remote repo）
  3. Discard——丟棄這次實作（git worktree 會被清理）

選 merge 或 PR，hermes 會幫你處理 git 操作。

你剛剛走過的完整流程

Brainstorming（釐清需求 + 設計）→ Git Worktree（隔離環境）→ Writing Plans（拆任務）→ SDD（子 agent 實作 + TDD + 自動 review）→ Code Review（最終檢查）→ Finishing（merge/PR）

這就是 superpowers 帶來的 Vibe Coding 流程——你只需要在關鍵節點做決定，其餘交給 skills 自動驅動。

加碼 A · 用 superpowers 除錯

之後程式出了 bug，不要直接叫 hermes 修——讓它觸發 systematic-debugging skill。superpowers 的除錯流程是 4 階段 root cause analysis：先重現、再縮小範圍、找到根因、最後修。比「你修一下」精確得多。

加碼 B · 寫自己的 skills

superpowers 裡有一個 writing-skills skill，教你怎麼寫自己的 SKILL.md。如果你有重複性的工作流程（例如：「每次部署前要做這五件事」），可以把它包成 skill，讓 hermes 自動遵循。

/writing-skills
加碼 C · 更新 superpowers

superpowers 持續更新。因為你是用 git clone 安裝的，更新就是：

cd ~/.hermes/skills/superpowers && git pull

然後 /new 重開對話。

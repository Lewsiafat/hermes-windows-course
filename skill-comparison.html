Claude Code Skills 比較指南

幫 Vibe Coder 選對工具，不裝錯、不裝太多

前言

前言 · Skill 是什麼？為什麼選錯很貴？

~3 分鐘

Claude Code 的 Skill（技能包）是一種 Markdown 格式的系統提示詞，裝上去之後會改變 Claude 的預設行為——讓它設計品味更好、流程更嚴謹、或是能連接外部工具。

聽起來全裝最好？不對。每個 Skill 都會佔用你的 context window（上下文視窗），裝太多等於讓 Claude 的「工作記憶」被說明書填滿，實際幫你做事的空間反而縮小。

這堂課要解決的問題

市面上流傳的 Claude Code Skill 包有幾十個，最熱門的有這 5 個：

  1. gstack — YC CEO Garry Tan 開源的 23 角色虛擬開發團隊
  2. Frontend Design — Anthropic 官方出品的 UI 美學注入器
  3. UI UX Pro Max — 社區製作的超大 UI 風格庫
  4. baoyu-skills — 寶玉老師的 22 個內容創作技能集
  5. NotebookLM Skill — 把 Claude 接到 Google NotebookLM 的橋接器

這五個適合的人完全不同，放在一起比較才能看清楚。

4 個 checkpoints

  1. 能說出每個 Skill 的核心差異（一句話）
  2. 知道哪兩個 Skill 裝在一起會打架
  3. 能用決策樹找到自己該裝哪個
  4. 知道「我已有 Superpowers 流程時」的正確做法

Step 2 / 5 · gstack 深度解析

~8 分鐘

它在解決什麼問題？

一個人做產品，要同時扮演工程師、設計師、QA、資安審計員、發布管理員……這些角色在真實公司裡是不同的人，每個人都有自己的專業視角和品質要求。gstack 把這些角色都做成 slash command，讓你在需要時「召喚」正確的視角。

23 個角色中最實用的 6 個

gstack 最好的使用方式

❌ 錯誤：開專案就把 23 個角色全部啟用

✅ 正確：功能做完 → 上線前 → 只呼叫你需要的角色做品質閘門

# 上線前跑安全掃描
/security-audit

# 功能完成後跑瀏覽器 QA
/qa

# 準備 release
/release

gstack 的弱點（誠實說）

  • Context 成本最高：23 個角色的系統提示詞佔用大量 context，長對話特別明顯
  • 與 Superpowers 打架：如果你已經有自己的開發流程（Spec → Plan → Build），gstack 的流程層跟你的流程會互相干擾。建議：只取你缺的點功能用（安全審計、QA），不要用它替換整套流程
  • Design QC 與 Frontend Design 衝突：兩個都有設計指引，Claude 會不知道聽誰的
⚠️ 如果你已經在用 hermes 的 Superpowers 流程

你的 Superpowers（SDD → Plan → Build → Loop）已經是一套完整的開發 Harness。gstack 的價值在於它的安全審計和 QA 測試——這兩塊是大多數個人開發者的盲點。

建議做法：只安裝 gstack 的 /security-audit 和 /qa 兩個角色，不要啟用整套流程層。

Step 3 / 5 · Frontend Design vs UI UX Pro Max

~8 分鐘

兩個 Skill 解決同一個問題

問題是：AI 生成的 UI 長得都一樣。永遠是 Inter 字體、藍紫漸層、圓角卡片。這不是 Claude 的錯，是沒有給它設計指引。

這兩個 Skill 都要解決這個問題，但方法不同：

Frontend Design（官方出品）

核心機制：在動手寫 code 之前，強制 Claude 先做美學決策——選風格、選色板、選字體。這種「強制承諾」才是它的真正價值，不是給你更多選擇。

規格：50 種設計風格 · 21 種色板 · 50 種字體配對 · 20 種圖表類型

禁用字體：Inter、Roboto、Arial、Space Grotesk（就是為了逼 Claude 有點個性）

支援框架：React、Next.js、Vue、Svelte、SwiftUI、React Native、Flutter、Tailwind

UI UX Pro Max（社區製作）

核心機制：提供更多選項。67 種 UI 風格（含 Glassmorphism、Aurora UI、Neumorphism 等潮流設計）、161 種色板、161 項推理規則。

規格：67 種 UI 風格 · 161 種色板 · 57 種字體配對 · 99 項 UX 指南 · 16 種技術棧

適合：你知道自己要什麼風格，Frontend Design 的 50 種選項不夠用時。

怎麼選？

如果你沒有特定風格偏好

→ 裝 Frontend Design。官方出品、最輕量、品質穩定。

如果你想要 Glassmorphism / Aurora UI / 賽博朋克 等特殊風格

→ 裝 UI UX Pro Max。但決策之前先想好要什麼風格——167 種選項太多容易選擇困難。

兩個都裝？

→ 千萬不要。兩套設計系統同時存在，Claude 會在兩個矛盾的設計指引之間搖擺，反而比沒裝更差。

實際使用方式

裝好後，在開始任何 UI 任務前，先告訴 Claude 你想要的風格：

我要做一個密碼生成器工具
設計風格：Cyberpunk Dark，主色霓虹綠 #00ff87
字體：等寬字體，有 hacker 感
幫我開始前先確認設計方向

Frontend Design 會讓 Claude 在寫第一行 code 之前先回覆設計決策，而不是一邊寫一邊亂猜。

Step 4 / 5 · baoyu-skills + NotebookLM Skill

~8 分鐘

這兩個 Skill 是給誰的？

如果你的主要產出是視覺內容（信息圖、漫畫、封面）或嚴肅研究寫作（有引文的文章），這兩個才跟你有關。做軟體產品的人可以跳過這個 Step。

baoyu-skills：內容創作者的軍火庫

由寶玉老師創建，22 個技能集合，覆蓋「內容理解 → 生成視覺素材 → 匯出壓縮 → 自動發佈」完整工作流。

最常用的 3 個技能

⚠️ 不要一次裝全部 22 個技能

作者寶玉老師自己的建議：按需安裝，每次只裝你要用的技能。22 個全裝的 context overhead 非常大，Claude 回答品質會下降。

建議做法：先裝 baoyu-infographic + baoyu-cover-image 這兩個最常用的，用到漫畫再另外裝 baoyu-comic。

NotebookLM Skill：研究型工作流橋樑

讓 Claude Code 直接查詢你在 Google NotebookLM 上傳的文獻，取得 Gemini 提供的有引文答案，再讓 Claude 用這些有來源的資料撰寫內容。

工作流程

  1. 把 PDF、URL、文獻上傳到 Google NotebookLM
  2. Claude 發問 → NotebookLM 查詢 → Gemini 給出帶引文的答案
  3. Claude 用有來源的資料撰寫文章或報告

重要限制

⚠️ 只支援本地 Claude Code CLI，不支援 Web UI（也不支援 hermes Web 介面）。如果你主要用 Telegram bot 或瀏覽器版 Claude，這個 Skill 對你無效。

適合場景

  • 學術寫作、論文研究
  • 需要引文支撐的嚴肅文章
  • 從大量文獻中提取有依據的資料

Step 5 / 5 · 決策樹 + 你的組合建議

~10 分鐘

決策樹：找到你的路線

🧑‍💻 我在做軟體產品 / Vibe Coding

  • 一個人做小工具 / MVP → Frontend Design（必裝）
  • 認真做要上線的產品 → Frontend Design + gstack（挑 Security + QA + Release）
  • 有團隊 → gstack 全套
  • 想要特殊 UI 風格 → UI UX Pro Max（取代 Frontend Design，二選一）

✍️ 我在做內容（文章、行銷、教學）

  • 需要視覺素材 → baoyu-skills（按需裝 2-3 個）
  • 需要引文支撐 + 本地 CLI → 加上 NotebookLM Skill

🔄 我已經有 hermes 的 Superpowers / SDD 開發流程

  • 你的 Harness 已經比 gstack 的流程層更適合你，不需要用 gstack 替換它
  • 只從 gstack 取你缺的點：/security-audit、/qa
  • 設計品味短板 → 加 Frontend Design（輕量，不干擾流程）

哪些組合會打架？

三種人的最終推薦

Solo Indie Hacker

必裝：Frontend Design（設計品味是快速開發最大的短板）
選裝：gstack 3 個角色（Release + Security + QA，上線前用）

不裝：UI UX Pro Max / baoyu-skills / NotebookLM

帶團隊做 Production 產品

必裝：gstack 全套（23 角色對應真實團隊分工）
選裝：Frontend Design（若團隊無設計師）

內容創作者 / 行銷人

必裝：baoyu-infographic + baoyu-cover-image
選裝：baoyu-comic（做教育內容才需要）
研究型加：NotebookLM Skill（本地 CLI 才能用）

不裝：gstack / Frontend Design / UI UX Pro Max

最後一句話

Skill 是 Harness，不是 Magic。
選 Skill 的最佳策略不是「裝最多」，而是「找到你最弱的環節，只補那一個」。

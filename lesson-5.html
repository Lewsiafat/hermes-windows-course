Lesson 5 · 進階使用：每日晨報自動化

把 cron + 自製 skill 串成「每天早上自動發晨報」的真實 workflow，30–40 分鐘

前言

前言 · 為什麼學「自動化 workflow」

~2 分鐘

Lesson 3 你學會了 cron 排程跟用 skill-creator 造 skill——但那是兩個分開的能力。這堂課把它們串成一條真實的 workflow：一個你自己造的 morning-brief skill，每天早上由 cron 自動觸發，把今天的天氣、新聞、提醒整理成一則晨報，推到你的手機。

★ 心智模型：每個自動化都是這四段

學會這條，你之後能自己設計任何自動化，不只晨報：

  1. trigger（觸發）— 什麼時候跑？這堂用 cron：每天 7:00。
  2. gather（蒐集）— 去哪拿資料？這堂用 hermes 內建 tool-use 抓天氣 + 新聞。
  3. compose（組裝）— 怎麼整理成人看的？這堂組成晨報格式。
  4. deliver（投遞）— 送到哪？這堂推到你的 channel（Telegram）。

關鍵設計：gather + compose 包進一個 skill（可重用、跟 channel 無關），trigger 跟 deliver 交給 cron。這就是為什麼一個 skill 能同時服務 Telegram 跟 LINE。

今天會做什麼

  1. Step 1：確認前置（hermes 在跑、Telegram 通、玩過 Lesson 3 的 cron）
  2. Step 2：用 skill-creator 造一個 morning-brief skill（v1：先只抓天氣）
  3. Step 3：用 cron 觸發這個 skill，5 分鐘後先看手機收到，再改成每天 7:00
  4. Step 4：重跑 skill-creator 把 skill 養大——加新聞頭條 + 今日提醒語
  5. Step 5：收尾 + 加碼（換 source / 多城市 / 換時間）+ 下次預告

4 個 checkpoints

  1. /morning-brief skill 造得出來、手動跑有產出（天氣）
  2. cron 5 分鐘測試 → 手機收到天氣晨報
  3. 改成每天 7:00、列得出這個 cron job
  4. skill 養大後 → 手機收到 ⟨天氣 + 新聞3條 + 提醒⟩ 完整晨報
必備：先做完 Lesson 1 + Lesson 2 + Lesson 3

這堂直接接在 Lesson 3 之後。還沒做過先回 Lesson 1（安裝 hermes）、Lesson 2（接 Telegram）、Lesson 3（cron + 造 skill）。本堂假設你的 Telegram bot 仍在跑、hermes gateway 也仍在跑、教學場景的 hermes model 是付費的（free model 對話式設定 cron / 造 skill 可能不會主動推理出該做的動作，得 fallback 到 slash command 手動跑）。

切換 provider / model：在 Telegram bot 或 TUI 傳 /model 查目前模型；傳 /model provider:model-name 切換，建議造 skill / 設 cron 時用付費 model（例 /model anthropic:claude-sonnet-4）。

⏰ 本堂假設你的機器是醒著的。「每天 7:00 自動發」只有在那個時間點 hermes gateway 還在跑時才會觸發。本堂聚焦 workflow 本身，「讓 hermes 24/7 常駐（開機自啟、systemd 服務）」是下一課的主題——這堂先用「機器醒著」當前提。

Step 1 / 5 · 開始之前

~3 分鐘

動手前花一分鐘確認三件事都還活著——這堂全部建立在它們之上：

1. hermes gateway 在跑

WSL Ubuntu 終端機跑：

sudo $(which hermes) gateway status --system

看到 running 就好。沒在跑就 sudo $(which hermes) gateway restart --system。

2. Telegram bot 通

打開手機 Telegram，找你 Lesson 2 接好的 bot，隨便傳一句 hi，確認它有回。這堂的晨報最後會推到這裡。

3. 你玩過 Lesson 3 的 cron + skill-creator

這堂不重教 cron 跟 skill-creator 的基本操作——如果 Lesson 3 的「5 分鐘後推 Telegram」跟「用 skill-creator 造 skill」你都做過一次，就可以往下。沒做過先回 Lesson 3。

三項都 OK → 往 Step 2 造你的第一個 skill。

Step 2 / 5 · 造 morning-brief skill（v1：先只抓天氣）

~8 分鐘（★ 先把 skill 本體打通）

漸進堆疊的第一步：先做最小可行版本——skill 先只做「抓台北天氣、組成一則早安訊息」。等下 Step 3 確認「cron 觸發 → 推手機」這條管線通了，Step 4 再把新聞、提醒加進來。一次只解一個風險。

1. 用 skill-creator 開造

在 hermes TUI 跑 /skill-creator，給這顆種子 prompt：

幫我造一個叫 morning-brief 的 skill。工作是：抓台北今天的天氣和降雨機率，整理成一則簡短的早安晨報訊息。

2. 看到「evaluation / benchmarks / test cases」就講「不用」

跟 Lesson 3 一樣，skill-creator 中途會問要不要設 evaluation。直接回：

不用 eval，只 vibe 就好。

3. skill 寫完、讓它生效

skill-creator 會把檔案寫到類似 ~/.hermes/skills/productivity/morning-brief/SKILL.md（類別可能不同）。讓它生效最快的方式：傳 /new 開新對話，或 /reload-skills。

4. 手動跑一次驗證

在 hermes CLI 或 Telegram bot 跑：

/morning-brief

應該吐回一則「早安！台北今天…」帶天氣 + 降雨機率的訊息。

✓ skill 造得出來、手動跑有天氣產出 → checkpoint 1 完成。skill 本體打通，下一步交給 cron 自動跑。

🚨 我卡住了

講「幫我造」之後 hermes 沒主動動作

免費 model 推理力可能不足。fallback 直接在 TUI 打 /skill-creator 進訪談模式，再貼上面那段需求。

造完 /morning-brief 認不出來

  1. 傳 /new 或 /reload-skills 重載一次
  2. 還不行：ls ~/.hermes/skills/*/ 看 morning-brief 是否真的落地、實際在哪個類別
  3. 確認 gateway running：sudo $(which hermes) gateway status --system

天氣抓不到 / 數字怪怪的

那是 hermes 的 web / tool-use 議題、不是 skill 本身的問題。對它講「再跑一次 morning-brief」通常就好。天氣是 Lesson 3 已驗證能穩定抓的，多試一次。

Step 3 / 5 · 用 cron 觸發這個 skill

~8 分鐘（★ 打通「自動跑 → 推手機」管線）

skill 本體有了，現在讓它自動跑。先用「5 分鐘後一次性測試」確認管線通，再改成每天 7:00 永久排程。

1. 對 hermes 講「5 分鐘後跑 morning-brief」

在你的 Telegram bot（或 TUI）貼：

5 分鐘後跑一次 morning-brief，把結果推到 Telegram。
💡 其實「推到 Telegram」可以不寫。hermes 的 cron 投遞會自動跟著「你在哪個 channel 建這個 cron」走——你從 Telegram bot 設，它就推 Telegram；做過 Lesson 4 的人從 LINE 設，它就推 LINE。同一個 skill、同一條 cron，channel 跟著你走。寫上「推到 Telegram」只是更保險。

hermes 會把設定寫進 ~/.hermes/cron/jobs.json（WSL Ubuntu 主機，hermes 幫你寫，不用手寫 json）。

2. 等 5 分鐘，看手機

5 分鐘到時，你的 Telegram bot 應該主動推一則天氣晨報過來。

✓ 手機收到 cron 推送的天氣晨報 → checkpoint 2 完成。cron → skill → 手機這條管線打通了，剩下就是把它變每天、把 skill 養大。

3. 改成每天 7:00 永久排程

對 hermes 再講一句：

把 morning-brief 改成每天早上 7:00 跑。

明天 7:00（只要那時 gateway 還在跑）手機就會自動收到。

4. cron 管理三式

之後想調整，都是對 hermes 講一句話：

列出我現在所有 cron 排程。
把 morning-brief 改成每天早上 7:30。
刪掉 morning-brief 的排程。

也可以 WSL 直接看設定檔：

cat ~/.hermes/cron/jobs.json
🚨 我卡住了

5 分鐘到了手機沒收到

多半是 gateway 沒拿到新 cron：

  1. sudo $(which hermes) gateway restart --system 重啟
  2. tail -n 50 ~/.hermes/logs/gateway.log 看有沒有錯誤
  3. 確認 ~/.hermes/cron/jobs.json 真的有那條 job（cat ~/.hermes/cron/jobs.json）

推錯 channel / 沒推到 Telegram

投遞跟著「你建 cron 的 channel」走。如果你是在 TUI 設的，它可能推到別處。從 Telegram bot 裡重設一次這條 cron，投遞就會綁定 Telegram。Telegram bot 本身沒回應的話，先回 Lesson 2 確認 bot 還活著。

hermes 沒主動寫 jobs.json

免費 model 推理力可能不足。對它講更明確：「請編輯 ~/.hermes/cron/jobs.json，加入一條每天 7:00 跑 morning-brief 的 job」，把 file path 直接點出來。

Step 4 / 5 · 把 skill 養大：加新聞 + 提醒

~8 分鐘（★ 漸進堆疊最後一層）

管線通了、skill 也跑得起來，現在回去把同一個 skill 養大。不重造、不手寫 SKILL.md——一樣用 skill-creator，叫它修訂既有的 morning-brief。

1. 重跑 skill-creator 修訂既有 skill

在 hermes TUI 跑 /skill-creator，講：

幫我把 morning-brief 加兩件事：(1) 今天 3 條重點新聞頭條 (2) 結尾加一句今日提醒語。順序：天氣 → 新聞 → 提醒。

它會訪談一次（比第一次短）、改寫同一份 SKILL.md。

2. 重載 + 手動跑看完整版

傳 /new 或 /reload-skills 重載，再跑一次 /morning-brief。這次應該天氣、新聞、提醒三段都在，像這樣：

早安！台北今天 🌧️ 毛毛雨，25.1°C ~ 35.7°C，降雨機率 76%。記得帶傘喔 ☔，天氣熱，多喝水 💧

📰 今日頭條
• 台灣也被點名！川普擬重築關稅壁壘 恐課徵至少10% — 東森新聞
• 把握好天氣！6/5 起迎「梅雨旺盛期」全台防致災雨 — Yahoo新聞
• 船身炸大洞！伊朗官媒公布「貨輪遇襲片」 — ETtoday新聞雲

💬 好事會發生在努力的人身上 🌟

3. 不用再碰 cron

注意——你沒有動 cron。Step 3 那條 cron 只是說「跑 morning-brief」，skill 改了，它每天 7:00 跑的內容就自動變完整版。這就是「skill 負責內容、cron 負責觸發＋投遞」分工的好處。

✓ 手機收到 ⟨天氣 + 新聞3條 + 提醒⟩ 完整晨報 → checkpoint 4 完成。Lesson 5 全部 4 checkpoints 達標。

🚨 我卡住了

新聞抓不到 / 內容怪怪的

那是 hermes 的 web / tool-use 議題、不是 cron 也不是 skill 結構的問題。處置：對它講「再跑一次 morning-brief，這次補上 3 條真實新聞頭條」。真的當天抓不到也沒關係——晨報以「天氣 + 提醒」就成立，新聞當加分。不要為了湊新聞把晨報改成只有新聞一項。

skill-creator 另造了一個新 skill、沒改到舊的

它有時會搞混。fallback：明確講「修改既有的 morning-brief skill，不要新建」。真的多造了就把多餘的刪掉：rm -rf ~/.hermes/skills/*/⟨多餘的名字⟩。

改完沒生效

傳 /new 重開對話（最快），或 /reload-skills，再跑一次 /morning-brief。

Step 5 / 5 · 完成 + 加碼

~3 分鐘

恭喜，你把 cron + skill 串成了第一條真實自動化 workflow。4 個 checkpoints 都完成：

  1. ✓ /morning-brief skill 造得出來、手動跑有產出（天氣）
  2. ✓ cron 5 分鐘測試 → 手機收到天氣晨報
  3. ✓ 改成每天 7:00、列得出這個 cron job
  4. ✓ skill 養大後 → 手機收到 ⟨天氣 + 新聞3條 + 提醒⟩ 完整晨報

你剛剛串起來的這條鏈

cron（每天 7:00 觸發）→ morning-brief skill（抓天氣+新聞、組裝、加提醒）→ 投遞到你的 channel → 手機。記住這四段（trigger / gather+compose / deliver），任何自動化都是這個形狀。

加碼 A · 換 source，做你自己的晨報

晨報內容是 skill 決定的，再跑一次 skill-creator 就能換。例：

幫我改 morning-brief：把新聞換成「今天台股加權指數 + 美元台幣匯率」，其他不變。

（財經數字 hermes 不一定每次抓得到，抓不到就退回新聞或天氣——保持「多 source 一次」的精神，別降成單一項。）

加碼 B · 多城市天氣

常出差或關心親友所在地：

幫我改 morning-brief：天氣改成台北、東京、舊金山三個城市一起報。
加碼 C · 換時間 / 加一條晚報

cron 那條隨時可調：

把 morning-brief 改成每天 6:30 跑。

想要晚上也來一份？再設一條 cron 指到同一個 skill 即可：

再設一條 cron，每天晚上 21:00 也跑一次 morning-brief。

Git 版本控制入門

從本地 → GitHub，建立你的 AI 開發安全網

前言

前言 · 為什麼 AI 開發者一定要學 Git

2 分鐘了解它能幫你避開哪些災難

你有沒有遇過這些情況：

  • 改了一段 code，AI 幫你改到一半，結果跑不動了，也不知道原本長什麼樣子
  • 請 Claude Code 修 bug，越改越亂，想回到昨天那個「還可以用」的狀態
  • 電腦壞掉、硬碟掛點，做了一個月的 code 全部消失
  • 同一份專案你改了，朋友也改了，合在一起全部爛掉

Git 就是解決這些問題的工具。 它是一個「時光機 + 安全網」——讓你在 AI 輔助開發的過程中，大膽嘗試，出錯了隨時回頭。

Git 對 AI 開發特別重要的 3 個理由

🛡️ 理由 1：AI 改壞了，一個指令就回去

Claude Code、Cursor、GitHub Copilot 幫你改 code 時，它不一定每次都改對。有了 Git，你每次讓 AI 動大手術之前都可以先 git commit，如果改壞了，一行 git checkout 馬上回到上一個版本，完全不慌。

沒有 Git 的情況：改壞了，Ctrl+Z 到懷疑人生，或者直接重寫。

📚 理由 2：整個開發歷程都留著

Git 的 commit 歷史就是你的開發日記。你可以看到「我三週前做了什麼決定」、「這個 bug 是哪次改動引入的」、「這個功能是何時加的」。當 AI 幫你寫 code，這份歷史紀錄更有價值——你可以追蹤每次 AI 的建議是否改善了系統。

☁️ 理由 3：GitHub 是你的雲端備份 + 作品集

把 code 推到 GitHub，電腦壞掉也不怕，換電腦照樣繼續工作。而且 GitHub 上的專案就是你最真實的技術作品集，不需要寫履歷，直接讓別人看你的 code。

這堂課學完你會做到什麼

  • ✅ 在本地端用 Git 管理你的專案（init / add / commit）
  • ✅ 申請 GitHub 帳號並建立第一個 Repository
  • ✅ 設定 SSH Key，安全地連接本地和 GitHub
  • ✅ 把本地專案推送到 GitHub（push）
  • ✅ 看懂 commit 歷史，知道如何回到任何一個版本

整個流程約 45 分鐘。按「下一步」開始。

Step 1 / 7 · 確認 Git 已安裝

WSL2 / macOS 幾乎內建，Windows 原生需要另裝

先確認你的環境有沒有 Git：

git --version

如果看到 git version 2.x.x，代表已經安裝好了，跳到 Step 2。

🐧 WSL2（Ubuntu）— 沒有 git 的話 
sudo apt update && sudo apt install git -y

裝完再跑一次 git --version 確認。

🍎 macOS — 沒有 git 的話

方法一（推薦）：安裝 Homebrew 後執行

brew install git

方法二：直接輸入 git，macOS 會提示你安裝 Xcode Command Line Tools，按確認就好。

🪟 Windows 原生（不使用 WSL2）

前往 git-scm.com 下載安裝程式，一路 Next 即可。安裝完開啟 Git Bash 使用。

⚠️ 建議優先使用 WSL2，體驗更接近 Linux / macOS，指令完全通用。

設定你的身份（只需做一次）

Git 每一個 commit 都會記錄是誰做的。先告訴 Git 你是誰：

git config --global user.name "你的名字"
git config --global user.email "你的email@example.com"

這裡的 email 之後要跟 GitHub 帳號的 email 一致，commit 才會連結到你的帳號。

確認設定：

git config --global --list

Step 2 / 7 · 本地端基礎：init / add / commit

三個指令就能追蹤你的所有變動

Git 最核心的工作流程只有三步：初始化 → 加入追蹤 → 提交快照。我們先建立一個練習用的專案。

建立練習專案

mkdir my-first-git && cd my-first-git

Step ① — git init：初始化 Git 倉庫

在這個目錄裡啟動 Git 的時光機：

git init

你會看到 Initialized empty Git repository in .../my-first-git/.git/。Git 在背景建立了一個隱藏的 .git/ 資料夾，所有版本歷史都存在裡面。

建立第一個檔案

echo "# My First Project" > README.md

查看 Git 目前狀態：

git status

你會看到 README.md 顯示為 Untracked files（紅色）——代表 Git 看到這個檔案，但還沒開始追蹤它。

Step ② — git add：把變動加入暫存區

把 README.md 加入「等待提交」的暫存區：

git add README.md

或者一次加入所有變動的檔案：

git add .

再跑一次 git status，會看到 README.md 變成綠色的 Changes to be committed。

Step ③ — git commit：提交快照（存檔點）

把暫存區的內容正式存成一個版本，加上說明訊息：

git commit -m "初始化專案：加入 README"

🎉 恭喜！你存了第一個版本。查看 commit 歷史：

git log --oneline
💡 commit 訊息怎麼寫？

好的 commit 訊息讓未來的你（和 AI）能快速理解「這次改了什麼、為什麼改」：

  • ✅ feat: 新增使用者登入功能
  • ✅ fix: 修正首頁載入失敗的 bug
  • ✅ docs: 更新 README 安裝說明
  • ❌ update（什麼都沒說）
  • ❌ asdfasdf（隨便打）
💡 如何回到過去的版本？

先找到你想回去的 commit 的 hash（7 碼縮寫）：

git log --oneline

回到那個版本（只是查看，不會影響現在的進度）：

git checkout abc1234

回到最新版本：

git checkout main

Step 3 / 7 · 申請 GitHub 帳號

全球最大的 code 儲存平台，免費使用

GitHub 是你的雲端 Git 儲存庫。把 code 推到 GitHub，就能從任何地方存取、備份，也能跟別人協作。

申請步驟

  1. 前往 github.com/signup
  2. 輸入 Email → 設定密碼 → 選擇 Username（這會是你的公開 ID，想清楚）
  3. 驗證 email（收信箱確認信）
  4. 選擇免費方案（Free），功能已完全夠用
💡 Username 怎麼取？

你的 GitHub URL 是 github.com/你的Username，等於你的技術名片。建議：

  • 用真實姓名或常用網路 ID（例如 lewsiafat）
  • 全小寫，可以有連字號（-）
  • 避免隨機數字，未來給別人看不太好

設定個人檔案（選做）

登入後到 Settings → Profile，填上名字、頭像、一行自我介紹。你的 GitHub 個人頁就是技術作品集，值得花 5 分鐘設定好。

確認帳號建立成功

登入 GitHub 後，你應該看到自己的 Dashboard。URL 是 https://github.com/你的Username。

帳號建立好了，下一步建立你的第一個 Repository（遠端專案）。

Step 4 / 7 · 在 GitHub 建立遠端 Repository

Repository = 一個專案的雲端家

Repository（簡稱 Repo）是 GitHub 上存放一個專案所有 code 和歷史記錄的地方。我們來建立一個。

建立步驟

  1. 登入 GitHub，點右上角的 + → New repository
  2. 填寫：
    • Repository name：my-first-git（跟你本地的資料夾同名，比較直觀）
    • Description：可以留空，或寫「練習用的第一個 Git 專案」
    • Visibility：選 Public（公開，免費；Private 是私有）
  3. ⚠️ 不要勾選 "Add a README file"、"Add .gitignore"、"Choose a license"——因為我們本地已經有 commit 了，GitHub 有東西的話之後推送會衝突
  4. 點 Create repository

建立後你會看到什麼

GitHub 會顯示一頁「快速設定」指令。你會看到三個選項：

  • ...or create a new repository on the command line（你本地還沒有 repo 的情況）
  • ...or push an existing repository from the command line（我們的情況）
  • ...or import code from another repository

先把這頁放著，下一步設定 SSH Key 後，我們就會用到 "push an existing repository" 的指令。

💡 Public vs Private，我該選哪個？
  • Public：任何人都能看到你的 code，但你可以控制誰能修改。練習、開源專案、作品集用 Public。
  • Private：只有你和你指定的人能看到。含有 API key、商業機密的專案用 Private。
  • ⚠️ 不管 Public 還是 Private，永遠不要把 .env 檔案、API Key、密碼推到 GitHub。

Step 5 / 7 · 建立 SSH Key

讓你的電腦和 GitHub 建立安全的信任關係

推送 code 到 GitHub 需要「證明你是你」。推薦用 SSH Key——比每次輸入密碼更安全、更方便。

什麼是 SSH Key？

SSH Key 是一對密鑰：私鑰（存在你電腦，絕對不能給別人）+ 公鑰（上傳到 GitHub，讓 GitHub 認識你）。就像門鎖和鑰匙——公鑰是鎖，私鑰是鑰匙，只有你的鑰匙能開這把鎖。

① 生成 SSH Key

用你的 GitHub email 建立 SSH Key（ed25519 是目前最推薦的演算法）：

ssh-keygen -t ed25519 -C "你的email@example.com"

接下來會問你：

  • Enter file in which to save the key：直接按 Enter，使用預設路徑 ~/.ssh/id_ed25519
  • Enter passphrase：可以設定密碼（更安全），或直接 Enter 跳過（方便）。練習用可以跳過。

② 查看你的公鑰

cat ~/.ssh/id_ed25519.pub

你會看到一段以 ssh-ed25519 開頭、以 你的email 結尾的長字串。複製整行（包含開頭的 ssh-ed25519 到結尾的 email）。

③ 把公鑰加到 GitHub

  1. 登入 GitHub → 右上角頭像 → Settings
  2. 左側選單選 SSH and GPG keys
  3. 點綠色的 New SSH key
  4. Title：輸入一個容易辨識的名字（例如「我的 MacBook」或「WSL2 Ubuntu」）
  5. Key：貼上剛才複製的公鑰
  6. 點 Add SSH key，輸入 GitHub 密碼確認
⚠️ 常見錯誤：複製公鑰時多了換行

有些終端機複製時會在結尾多一個換行符，導致 GitHub 顯示格式錯誤。確認你複製的內容是一整行，沒有多餘的空白或換行。可以用這個指令直接複製到剪貼簿（macOS）：

pbcopy < ~/.ssh/id_ed25519.pub

WSL2 上：

cat ~/.ssh/id_ed25519.pub | clip.exe

Step 6 / 7 · 設定本地端 SSH 存取 GitHub

讓 git 指令自動使用正確的 SSH Key

測試 SSH 連線是否成功

先確認 GitHub 認識你的 SSH Key：

ssh -T git@github.com

第一次連線會問你是否信任 github.com，輸入 yes。

如果看到 Hi 你的Username! You've successfully authenticated...，就成功了！🎉

❌ 如果看到 Permission denied (publickey)

代表 GitHub 沒認到你的 key。常見原因：

  1. 公鑰沒有正確加到 GitHub（回 Step 5 確認）
  2. SSH agent 沒有載入私鑰，執行：
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

再測試一次 ssh -T git@github.com

（選做）設定 SSH Config 檔

如果你有多個 GitHub 帳號，或想指定特定 key，可以建立 SSH 設定檔：

mkdir -p ~/.ssh && nano ~/.ssh/config

加入以下內容（然後 Ctrl+X → Y → Enter 儲存）：

Host github.com
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_ed25519

設定 Git 預設分支名稱

現代 GitHub 預設主分支叫 main（舊版叫 master）。讓你本地 Git 也用 main：

git config --global init.defaultBranch main

Step 7 / 7 · 實戰：推送本地專案到 GitHub

把你在 Step 2 建立的本地專案推上雲端

回到 Step 2 建立的 my-first-git 目錄：

cd ~/my-first-git

① 連結本地 repo 和 GitHub 遠端

把 GitHub 上的遠端 repo 位址告訴你的本地 Git（把 你的Username 換成你的 GitHub 帳號）：

git remote add origin git@github.com:你的Username/my-first-git.git

確認遠端設定成功：

git remote -v

你會看到 origin 指向你的 GitHub repo（fetch 和 push 各一行）。

② 把本地 commit 推送到 GitHub

git push -u origin main

-u origin main 的意思是：把本地的 main 分支推到遠端的 origin，並建立追蹤關係。之後只需要打 git push 就夠了。

成功的話終端機會顯示進度條，最後顯示 Branch 'main' set up to track remote branch 'main' from 'origin'。

③ 去 GitHub 確認

打開瀏覽器，前往 https://github.com/你的Username/my-first-git，你應該看到你的 README.md 顯示在頁面上了！

之後的日常工作流程

每次改完 code，執行這三行就好：

git add .
git commit -m "說明這次改了什麼"
git push
💡 從 GitHub 拉取最新版本（git pull）

如果你在另一台電腦修改了 code，或跟別人協作，要先拉取最新版本：

git pull

這等於 git fetch（下載遠端更新）+ git merge（合併到本地）。

💡 .gitignore：讓 Git 忽略某些檔案

有些檔案不應該推到 GitHub（API Key、密碼、系統暫存檔）。在專案根目錄建立 .gitignore，Git 就會自動忽略這些檔案：

echo ".env" >> .gitignore
echo "node_modules/" >> .gitignore
echo "__pycache__/" >> .gitignore
git add .gitignore
git commit -m "加入 .gitignore，忽略敏感檔案"

⚠️ 如果你不小心把 .env 推上去了，即使之後刪掉，歷史記錄裡還是看得到。要用 git filter-branch 或 BFG Repo Cleaner 清除歷史，並且立刻更換 API Key。

🎉 完成！你現在會了：

  • ✅ git init → 初始化本地 repo
  • ✅ git add + git commit → 存版本快照
  • ✅ 申請 GitHub 帳號並建立 Repository
  • ✅ 建立 SSH Key 並設定到 GitHub
  • ✅ git remote add + git push → 推送到雲端

接下來可以：把你的 hermes-agent 設定目錄（~/.hermes）也用 Git 管理（記得 .gitignore 排除 .env！），這樣換電腦或設定出問題時，一個 git clone 就能還原。

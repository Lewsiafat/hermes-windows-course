前言

前言 · 為什麼把 hermes 接到 Telegram

1 分鐘

Lesson 1 你已經在 WSL 裡裝好 hermes、做過第一次對話。但你只能坐在電腦前面跟它講話——這堂 30–45 分鐘的延伸課要把這個限制拿掉：把 hermes 接到 Telegram，從手機就能跟它對話。

結束時你會有

  1. ✓ 一支自己的 Telegram bot（透過 BotFather 申請）
  2. ✓ 你自己的 Telegram user_id（讓 bot 只回你一個人）
  3. ✓ hermes gateway 在 WSL 背景跑著
  4. ✓ 至少一次「手機傳訊 → bot → hermes 回覆」的完整來回

限制：機器要開著

本堂用的是 polling 模式（hermes 每隔幾秒主動問 Telegram「有新訊息嗎」），所以你的 Windows + WSL 必須開著、gateway 必須跑著，bot 才有回應。Windows 重啟後 gateway 會掛掉、要手動重跑。「24/7 不間斷服務 / 自動啟動 / 雲端部署」不在本堂範圍，留給後續課程。

已經在 Lesson 1 Step 9 加碼 B 申請過 token？

很好——Step 2 你可以直接跳到「貼到 Notes 暫存」那段，不必重做 BotFather 流程。沒做過也沒關係，Step 2 會帶你完整走一次。

沒做過 Lesson 1？

本堂預設你已完成 Lesson 1（hermes 在 WSL 裝好、可對話）。沒做過請先去 Lesson 1，再回來。

Step 2 / 8 · 申請 Telegram bot

~5 分鐘

Telegram 的 bot 申請流程超簡單，2 分鐘搞定：跟 @BotFather 講話、回答幾個問題、拿到一段 token。

跟著走

已經有一份完整的中文教材，照著做就好：

→ 開啟 Telegram Bot 申請教材

跟完到「拿到 HTTP API token」那一步即可，token 暫存到記事本，等下 Step 4 要貼進去。

token 長什麼樣？

BotFather 回的 token 大概長這樣：

1234567890:ABCdefGHIjklMNOpqrsTUVwxyz0123456789

冒號前是 bot 的數字 ID，冒號後是 secret。整段都要。

🚨 主連結打不開（lewsi.ddns.net 失聯）

備援精簡版，5 句搞定：

  1. 手機/電腦 Telegram 開 @BotFather
  2. 送 /newbot
  3. 填 bot 顯示名稱（任意，例：my-hermes）
  4. 填 bot username（必須以 bot 結尾，且全網唯一，例：my_hermes_xyz_bot 或 myhermesbot）
  5. BotFather 回的訊息裡會有一段 HTTP API token，整段複製到記事本

username 取太常見的會撞名，加亂數或日期通常就過了。

BotFather 還能做什麼？（之後想玩再回來）
  • /setname：改顯示名稱
  • /setdescription：改 bot 自我介紹
  • /setuserpic：換頭像
  • /mybots：列出你所有 bot

關閉 Group Privacy（加群組用）

如果你之後想把 bot 加進 Telegram 群組，預設的 Privacy Mode 會讓 bot 只看得到 /指令，一般訊息全看不到。現在就先關掉，省得之後群組沒反應找半天原因。

  1. 開 @BotFather，送 /mybots
  2. 選你剛建的 bot
  3. 點 Bot Settings
  4. 點 Group Privacy
  5. 點 Turn off（關閉後顯示 Privacy mode is disabled）
⚠️ 只跟 bot 私聊的話這步可以跳過，但建議現在就做——之後加群組才不會踩坑。

✓ token 在手、Group Privacy 已關，接著 Step 3。

Step 3 / 8 · 拿你的 Telegram user_id

~2 分鐘

hermes gateway 設定時會問你「哪些 Telegram 使用者可以跟這支 bot 講話」——這個白名單填的是 數字 user_id，不是 @username。下面 30 秒拿到。

動作

  1. 手機/電腦 Telegram 開 @userinfobot
  2. 按下方「Start」（或送 /start）
  3. 它會立刻回一段話，裡面有 Id: 123456789（純數字，9–10 位數）
  4. 把那串純數字複製到記事本，跟 Step 2 的 token 放一起
user_id 是什麼？為什麼要它？

每個 Telegram 帳號都有一個唯一的數字 ID，跟 @username 不同——username 你可以隨時改、刪，但 user_id 跟著帳號一輩子。

hermes gateway 啟動後，每收到一則訊息會檢查 這個 user_id 在不在 allowlist 裡，不在就拒絕回覆。所以這個欄位填的是「哪個 Telegram 人類帳號允許用這支 bot」，不是 bot 自己的 ID。

Id 跟 Bot ID 怎麼分？

@userinfobot 回的訊息有時會列好幾項（Id、First Name、Last Name、Username、Language）。取最上面那個 Id，那是你（人類）的 ID。Bot 自己的 ID 不會出現在這裡。

✓ user_id 抄好了？接著 Step 4 把 token 跟 user_id 一起餵給 hermes。

Step 4 / 8 · hermes gateway setup

~8 分鐘

hermes gateway setup 是 hermes 把外部聊天平台接進來的設定精靈。我們要選 telegram、貼 Step 2 的 token、貼 Step 3 的 user_id。

動作

  1. 打開 Ubuntu 終端機，啟動精靈
hermes gateway setup
  1. 依下面 3 個提示一個一個填

3 個提示怎麼答

提示選 / 填
Choose gateway用方向鍵選 telegram，Enter
Telegram bot token⚠️ 建議手動 key in（同 Lesson 1 Step 7 的 paste 雷），或先看下面「補救」section 用 sed 寫進 .env。若還是要 paste：Ctrl+Shift+V，Enter
Allowed users貼 Step 3 的純數字 user_id，多人用逗號分隔（本教材只填你自己）。Enter

看到 Setup complete! 就成功，~/.hermes/.env 裡會多兩行 TELEGRAM_BOT_TOKEN= 與 TELEGRAM_ALLOWED_USERS=。

Allowed users 是什麼？為什麼要填？

沒這個欄位的話，bot 是公開的——任何陌生人 Telegram 搜到你 bot 就能丟訊息進來，你的 OpenRouter 帳號就會被陌生人花錢。Allowed users 只放你自己（或團隊夥伴）的 user_id，其他訊息會被 gateway 直接 ignore。

補救：直接改 hermes 的 .env

跟 Lesson 1 Step 7 同根因（hermes 上游 paste 雷）、同模式。下面兩個版本擇一用：

Variant A · 互動腳本（推薦）

輸入時 token 不會回顯（避免肩膀後面被看到）、user_id 會回顯（純數字無妨）：

cd ~/.hermes && read -sp "Paste your Telegram bot token: " TOKEN && echo && read -p "Paste your Telegram user_id: " USER_ID && sed -i "s/^TELEGRAM_BOT_TOKEN=.*/export TELEGRAM_BOT_TOKEN=$TOKEN/" .env && sed -i "s/^TELEGRAM_ALLOWED_USERS=.*/export TELEGRAM_ALLOWED_USERS=$USER_ID/" .env && unset TOKEN USER_ID

Variant B · 手動範本

把 YOUR_BOT_TOKEN 與 YOUR_USER_ID 替換成實際值再貼進終端機：

cd ~/.hermes && sed -i 's/^TELEGRAM_BOT_TOKEN=.*/export TELEGRAM_BOT_TOKEN=YOUR_BOT_TOKEN/' .env && sed -i 's/^TELEGRAM_ALLOWED_USERS=.*/export TELEGRAM_ALLOWED_USERS=YOUR_USER_ID/' .env

跑完任一個之後，下一步直接進 Step 5 啟動 gateway。

Step 5 / 8 · 啟動 hermes gateway（背景）

~5 分鐘

Token 跟 user_id 都進 .env 了，現在把 gateway 安裝成系統服務，這樣開機就自動跑、不需要每次手動啟動。

先試前景版（確認設定沒問題）

hermes gateway run

會看到一段啟動 banner（含「Press Ctrl+C to stop」）。確認沒有 401 / fatal 錯誤後，按 Ctrl+C 停掉，再進行下方的服務安裝。

安裝為系統服務

執行安裝指令。過程中會看到三個選項：

  • User service（不需 sudo，但關閉登入可能停止）
  • System service（開機自動啟動，以你的帳號身分執行）← 選這個
  • Skip service install for now

用方向鍵選第二項「System service」，按 Enter 確認。

sudo $(which hermes) gateway install --system --run-as-user

安裝完成後，啟動服務：

sudo $(which hermes) gateway start --system

確認跑著

hermes gateway status

預期看到類似：

✓ Gateway is running (PID: 12345)
  (Running manually, not as a system service)

沒看到「running」→ 看 log：

tail -n 50 ~/.hermes/logs/gateway.log

看 log（即時）

想盯著 gateway 的活動（debug、看訊息進來）：

tail -f ~/.hermes/logs/gateway.log

離開 tail -f 用 Ctrl+C（這只是退出觀察，不會停掉 gateway 本身）。

停掉 gateway

hermes gateway stop

萬一 stop 沒反應（極少見），fallback：

pkill -f "hermes gateway"

Step 6 / 8 · 第一次手機 ↔ hermes

~5 分鐘

Gateway 跑著、token 跟 user_id 都對，現在用手機驗證整條鏈路通了。

動作

  1. 打開手機 Telegram，搜尋你 Step 2 設的 bot username（一般是 @xxx_bot）
  2. 進到對話畫面，按下方「Start」（或送 /start）
  3. 傳第一句話，例如：hello, you there?
  4. 等 1–5 秒（看模型 response 速度），bot 應該會回
  5. 再傳一句相關的，例如：what was my first message?，確認 context 連動（hermes 應該記得你問過什麼）
看 gateway log 確認訊息有進來

另開一個 Ubuntu 終端機分頁、跑：

tail -f ~/.hermes/logs/gateway.log

傳訊時 log 應該會即時跑出新行，類似「Received message from user 12345」之類。

🚨 傳了訊息但 bot 沒回

看 ~/.hermes/logs/gateway.log，三類最常見：

  • log 顯示 unauthorized user → user_id 寫錯。回 Step 4 用 sed 補救改 TELEGRAM_ALLOWED_USERS=，hermes gateway restart。
  • log 完全沒新訊息 → bot username 找錯了（你連到的是別人的 bot）。回 BotFather 用 /mybots 確認你 bot 的 username 跟你 Telegram 對話畫面的 @ 一致。
  • log 有訊息進來、但回應 timeout / API error → OpenRouter 那邊的問題，看 log 有沒有 401（key 過期 / 額度不足）或 5xx（暫時故障）。
🚨 Telegram 完全找不到我的 bot
  • 確認 bot username 沒打錯（含 @）
  • 用瀏覽器開 https://t.me/<your_bot_username> 直接連
  • 還不行 → 回 BotFather /mybots，看你 bot 是不是被 BotFather 自動 disable 了（極少見）

✓ 傳訊有回 + context 對得上 → 4 個 checkpoints 完成，進 Step 7 收尾。

加碼 1：私訊（DM）vs 群組——兩種模式比較

hermes bot 支援兩種對話情境，行為稍有不同：

項目DM（私訊）群組（Group）
觸發方式直接傳訊即可預設需要 @ 提及 bot（見加碼 3）
Context每個人獨立 session同一群組 session，大家共用
隱私只有你跟 hermes 看得到所有群組成員都看得到
適合情境個人助理、私人任務團隊協作、共同查詢
allowlist要填 → 只有名單內的人可對話要填 → 群組每個人都要加進名單

💡 建議先用 DM 熟悉 hermes，再把 bot 加進群組——群組 context 共用，一個人 /new 會清掉所有人的記憶。

加碼 2：把 bot 加到 Telegram 群組

讓群組成員都能跟同一支 hermes 講話。

Step A · 確認 Group Privacy 已關

你在 Step 2 應該已經做過，保險起見再確認：

  1. 開 @BotFather，送 /mybots
  2. 選你的 bot → Bot Settings → Group Privacy
  3. 確認顯示 Privacy mode is disabled。如果是 enabled，點 Turn off
⚠️ Group Privacy 不關，bot 在群組裡只看得到 /指令，一般訊息和 @ 提及全看不到。

Step B · 加 bot 進群組

  1. 進到你的 Telegram 群組
  2. 點群組名稱 → Add Members（或 Edit → Members）
  3. 搜尋你 bot 的 username（例如 @my_hermes_bot）→ 加入
  4. 群組裡送 /start 測試（如果沒回，先看加碼 4 的 allowlist）

Step C · 把群組成員加進 allowlist

  1. 請每個要用 bot 的成員去 @userinfobot 查自己的 user_id
  2. 收集完後，在 terminal 跑：
sed -i "s/^export TELEGRAM_ALLOWED_USERS=.*/export TELEGRAM_ALLOWED_USERS=USER1,USER2,USER3/" ~/.hermes/.env

把 USER1,USER2,USER3 換成實際數字 id（逗號分隔，不能有空格）。

  1. 重啟 gateway 讓設定生效：
sudo $(which hermes) gateway restart --system
加碼 3：群組 @ Mention 觸發機制

hermes bot 在群組裡有兩種觸發模式，依你的群組使用情境選一個。

預設模式（每則都回）

只要發訊人在 allowlist 裡，群組裡每則訊息 bot 都會回應。適合小群或整群都是 hermes 使用者的情境。不需要設定，bot 加進群組就是這樣跑的。

Mention-only 模式（只回 @bot）

開啟後，群組裡只有明確 @ 你 bot 才會觸發回應，一般閒聊不理。適合混合群組（hermes 使用者跟非使用者都在）。

在 ~/.hermes/.env 加一行：

echo "export TELEGRAM_REQUIRE_MENTION=true" >> ~/.hermes/.env
sudo $(which hermes) gateway restart --system

Mention 的正確語法

寫法有效？說明
@my_hermes_bot 問題✓標準觸發，@ 放最前面
問題 @my_hermes_bot✓@ 放後面也可以
問題（沒有 @）✗Mention-only 模式下不觸發
Reply 到 bot 的訊息✓直接 reply 不需要 @
💡 混合群組建議開 Mention-only——避免 bot 打斷閒聊，只在有人需要時才出聲。
加碼 4：多人 Pairing — allowlist 管理

隨使用情境變化，你可能需要新增或移除有權限用 bot 的人。

查看目前 allowlist

grep TELEGRAM_ALLOWED_USERS ~/.hermes/.env

新增一個人

假設要加入 user_id 987654321：

sed -i "s/export TELEGRAM_ALLOWED_USERS=\(.*\)/export TELEGRAM_ALLOWED_USERS=\1,987654321/" ~/.hermes/.env
sudo $(which hermes) gateway restart --system

完全重設名單

sed -i "s/^export TELEGRAM_ALLOWED_USERS=.*/export TELEGRAM_ALLOWED_USERS=ID1,ID2,ID3/" ~/.hermes/.env
sudo $(which hermes) gateway restart --system

確認某人是否在名單裡

請那個人傳訊給 bot：有回 = 在名單；完全沒回 = 不在。進一步確認：

tail -n 30 ~/.hermes/logs/gateway.log | grep -i "unauthorized\|allowed\|rejected"

安全注意事項

  • allowlist 控制誰能消耗你的 AI API 額度，不要加不認識的人
  • bot username 公開時，不在名單的人傳訊會被靜默忽略（不報錯、不回應）
  • 定期跑 /usage 或上 OpenRouter Dashboard 確認用量沒有異常
加碼 2：傳語音訊息

hermes gateway 預設會把語音訊息自動轉文字再丟給模型——直接按 Telegram 對話框右下角的麥克風講就好，不用 /voice 之類指令。

轉字準確度看你 OpenRouter 帳號用什麼底層 ASR 模型。中文識別偶爾會不準，講慢一點會比較穩。

加碼 3：/new + /title 管理對話

傳 /new → 清掉目前 context，開全新對話（適合切話題、避免歷史污染）。

傳 /title 旅遊 → 給目前 session 一個名字；之後用 /resume 旅遊 找回，/sessions 列出所有已命名的 session。

傳 /usage → 看本次 session 用了多少 token、估算花了多少錢。

更多指令參考上方「日常常用指令速查」表。

加碼 4：/model 中途切模型

傳 /model（不帶參數）→ 看目前模型。傳 /model openrouter:deepseek/deepseek-r1-distill-llama-70b:free 或 /model anthropic:claude-sonnet-4 → 切到那個模型。語法是 /model provider:model。

費用敏感的話，預設用 OpenRouter free model、特定問題切貴的。

注意：只能切已經設定過的 provider。要新增 provider 請退出 chat、在 terminal 跑 hermes model 設定。

加碼 5：管理 gateway 服務

Step 8 / 8 · 附錄：進階 Telegram 設定

依需求選讀

這個附錄收錄 4 個進階情境，不需要全部設定——有需要時再來查即可。

附錄 A · Observer 模式：讀取群組訊息但不主動回覆

預設情況下，bot 看到訊息就回。Observer 模式讓 bot 靜靜讀取群組對話、把它當 context，只在被明確 @ 到才開口——特別適合「多數時候只是在旁邊聽，偶爾被叫才回話」的群組場景。

設定方式（兩擇一）

方式 A · 寫進 ~/.hermes/.env

echo "export TELEGRAM_OBSERVE_UNMENTIONED_GROUP_MESSAGES=true" >> ~/.hermes/.env
echo "export TELEGRAM_REQUIRE_MENTION=true" >> ~/.hermes/.env
sudo $(which hermes) gateway restart --system

方式 B · 寫進 ~/.hermes/config.yaml

telegram:
  require_mention: true
  observe_unmentioned_group_messages: true

行為說明

  • 沒有 @ bot：訊息被讀入 context，bot 不回覆
  • 有 @ bot（或直接回覆 bot 的訊息）：bot 用完整的對話 context 來回應
💡 建議搭配 TELEGRAM_GROUP_ALLOWED_CHATS 指定哪個群組可用，避免 bot 讀入不相關群組的 context。
附錄 B · Home Channel：讓 hermes 主動發通知到指定頻道 / 群組

Hermes 的 cron 排程（自動任務）需要一個地方回報結果。Home Channel 就是那個地方——你設定好之後，排程任務跑完會把輸出送到這個 chat。

方式一：用指令設定（推薦）

在你想設為 Home Channel 的 Telegram 對話（DM 或群組）傳送：

/sethome

Bot 會回覆確認，之後所有排程輸出都會送到這裡。

方式二：寫死進 .env

群組 ID 是負數（Telegram 規格），可從 bot log 裡看到。

echo "export TELEGRAM_HOME_CHANNEL=-1001234567890" >> ~/.hermes/.env
sudo $(which hermes) gateway restart --system

Forum 頻道（有 Topics）

如果你的群組開了 Topics，想把排程通知送到特定 topic：

echo "export TELEGRAM_CRON_THREAD_ID=<topic_thread_id>" >> ~/.hermes/.env
sudo $(which hermes) gateway restart --system

topic_thread_id 可在 Telegram 網頁版的 URL 看到（格式 ?thread=123）。

附錄 C · 群組進階設定（白名單、觸發詞、忽略 Thread）

整個群組授權（不用逐人加 user_id）

如果群組很大、成員常換，與其維護一份 user_id 名單，不如直接授權整個群組 chat：

echo "export TELEGRAM_GROUP_ALLOWED_CHATS=-1001234567890" >> ~/.hermes/.env
sudo $(which hermes) gateway restart --system

群組 ID 是負數，可在 bot log 或 Telegram 網頁版 URL 找到。

自訂觸發詞（mention_patterns）

除了 @ bot 之外，也可以設定一組關鍵字來觸發 bot——例如讓群組裡輸入「nano」就等同 @bot：

telegram:
  mention_patterns:
    - "^\\s*nano\\b"

支援正規表示式，不分大小寫。^\s* 代表從訊息開頭開始，\b 確保整詞匹配。

忽略特定 Thread（ignored_threads）

Forum 群組裡有些 topic 不想讓 bot 介入（例如公告、閒聊頻道）：

telegram:
  ignored_threads:
    - 31
    - 42
⚠️ 重要：改 Group Privacy 後要重新加 bot
如果你在 BotFather 修改了 Group Privacy 設定，必須把 bot 踢出群組再重新加入，設定才會生效。直接重啟 gateway 無效。
附錄 D · 同一個群組多支 bot 並存

想在同一個 Telegram 群組裡跑多個功能各異的 hermes bot（例如一支研究、一支記帳）？用 profile 機制。

核心規則

  • 每個 bot 需要自己獨立的 Telegram bot token（去 BotFather 申請）
  • 每個 profile 跑一個獨立的 gateway 實例
  • 絕對不要讓兩個 gateway 同時使用同一個 token

建立 profile 並啟動各自的 gateway

# 設定 research profile 的 gateway（問你 token 等）
hermes -p research gateway setup
# 啟動
hermes -p research gateway start
# 第二支 bot（ops）
hermes -p ops gateway setup
hermes -p ops gateway start

防止 bot 互相觸發（exclusive_bot_mentions）

群組裡同時有多支 hermes bot 時，要避免一則訊息同時觸發全部 bot。在每個 profile 的 config.yaml 加上：

telegram:
  require_mention: true
  exclusive_bot_mentions: true

效果：@research_bot 分析這份報告 只觸發 research bot，其他 bot 靜默。

💡 各 profile 的 config 在 ~/.hermes/profiles/<name>/config.yaml，token 在各自的 .env 裡。

附錄到此結束。日常使用不需要這些設定——需要時再回來查就好。

前言

前言 · 為什麼要比較這四個系列？

~5 分鐘

Claude Code 的 Skill 系統讓你可以「預裝」一套工作流程或最佳實踐，讓 AI agent 在每個 session 都照著來。但問題是——哪個系列適合你？

這次要比較的四個都屬於「Pre-Plan Skill」——在你開始工作之前就改變 agent 行為的系統級技能包，彼此定位不同但常被混淆：

🔵 Agent Skills

Addy Osmani（前 Google Chrome 工程總監）開源的 24 技能包，覆蓋軟體開發全生命週期。

addyosmani/agent-skills

🟡 Superpowers

Jesse Vincent / Prime Radiant 的 14 技能方法論，以 Sub-agent Driven Development（SDD）和嚴格 TDD 為核心。

obra/Superpowers

🟢 GStack

Y Combinator CEO Garry Tan 開源的 58 技能虛擬工程團隊——一人公司的虛擬 CEO、設計師、QA、安全官全配齊。

garrytan/gstack

🔴 GSD Core

社區驅動的 69 指令 + 34 agent 框架，從根本解決 AI 長 session 品質退化（context rot）問題。

open-gsd/gsd-core

學完這份指南你能做到什麼

  1. 能說出每個系列的核心定位（一句話）
  2. 知道哪些組合裝在一起會互相衝突
  3. 用決策樹找到最適合自己的系列
  4. 知道不同情境（快速原型、大型專案、品質控管）各該選哪個

🔵 Agent Skills — 軟體工程最佳實踐百科

Addy Osmani 把資深工程師的工作流程編碼為「流程，而非文章」。最大特色是每個技能都附有「反合理化表」——讓 AI 無法用藉口跳過步驟。

技能按開發流程分類：

interview-mespec-driven-development incremental-implementationtest-driven-development doubt-driven-developmentbrowser-testing-with-devtools security-and-hardeningperformance-optimization git-workflow-and-versioningshipping-and-launch …共 24 個

8 個 slash 指令：/spec → /plan → /build → /test → /review → /ship

🟡 Superpowers — Sub-agent 驅動開發方法論

不只是技能，而是一套完整的開發哲學。核心是 SDD（Sub-agent Driven Development）：agent 先規劃再執行，所有重型工作分派給 sub-agent，能自主運行數小時而不偏離。

subagent-driven-developmenttest-driven-development brainstormingwriting-plans executing-plansdispatching-parallel-agents using-git-worktreessystematic-debugging …共 14 個

✨ 特色：技能自動觸發，不需手動呼叫 slash 指令。雙階段審查（規格合規 + 程式碼品質）。

🟢 GStack — 虛擬工程團隊

Garry Tan 的核心信念：「在 AI 時代完整實作的邊際成本趨近於零」。58 個技能涵蓋 CEO 審查、設計諮詢、Playwright QA、安全審計到部署監控。

/office-hours/plan-ceo-review /plan-design-review/design-shotgun /qa/browse /cso/land-and-deploy /canary…共 58 個

✨ 特色：/office-hours YC 風格的創業診斷、內建 Playwright 瀏覽器 QA、多 AI 交叉驗證。

🔴 GSD Core — 上下文工程框架

解決 AI 最根本的問題：長 session 品質退化（context rot）。所有重型工作都在全新 200K token 上下文的 sub-agent 中執行，並透過 .planning/ 目錄（STATE.md、ROADMAP.md 等）跨 session 持久化狀態。

/gsd-new-project/gsd-spec-phase /gsd-plan-phase/gsd-execute-phase /gsd-verify-work/gsd-ship /gsd-autonomous/gsd-mempalace-capture …共 69 指令 + 34 agent

✨ 特色：兩階段命名空間路由（6 個路由 → 69 個指令）讓 idle token 成本極低（~120 tokens）。

獨家特色說明

🔵 Agent Skills 獨有：反合理化表（Anti-rationalization tables）

每個技能都明確列出「AI 可能給的藉口」和「為什麼這些藉口不成立」。防止 Claude 以「這個步驟太慢」或「這個情況不需要測試」等理由跳過重要流程。

🟡 Superpowers 獨有：SDD 雙階段審查

Sub-agent 完成後，不是直接合併，而是先做「規格合規審查」再做「程式碼品質審查」。這也是 PR 拒絕率高達 94% 的原因——真的很嚴格。

🟢 GStack 獨有：YC Office Hours (/office-hours)

模擬 Y Combinator 辦公時間的創業診斷對話。AI 會扮演 YC 合夥人，問「這個功能真的有人要付錢嗎？」、「你的增長飛輪是什麼？」。適合在動工前先釐清產品方向。

🔴 GSD Core 獨有：MemPalace 記憶宮殿

/gsd-mempalace-capture 讓 agent 把重要的技術決策、架構洞見存入結構化的記憶檔案，之後用 /gsd-mempalace-recall 跨 session 調出。可以跨好幾個月的專案維持上下文連貫性。

Step 3 / 5 · 衝突分析與組合建議

~8 分鐘

⚠️ 衝突組合（不要同時裝）

❌ Superpowers + GSD Core

兩者都有完整的「規劃 → 執行 → 驗證」流程，且都會 hook 到 session start。同時啟用，AI 不知道該遵循哪個方法論，行為不可預測。

❌ Superpowers + GStack

兩者都試圖控制整個開發流程，啟動機制可能互相干擾。GStack 的虛擬團隊角色和 Superpowers 的 SDD 流程設計理念根本不同。

❌ 任意三個以上全裝

絕對不要。Token 爆炸、流程衝突、AI 行為完全不可預測。只裝一個主系列，最多搭配一個輔助。

✅ 可以疊加的組合

✅ Agent Skills + GSD Core

最自然的組合。Agent Skills 作為個別技能參考（security、performance、doubt-driven-development），GSD Core 作為工作流骨架。兩者設計理念互補，衝突極低。

推薦給：中大型專案的進階 Vibe Coder

✅ Agent Skills + GStack 部分技能

只安裝 GStack 的工具性技能（/browse、/qa、/cso），搭配 Agent Skills 的完整開發流程。需要注意 CLAUDE.md 的合併方式。

推薦給：需要瀏覽器 QA 的全端開發者

✅ 單一系列全用（最乾淨）

選一個你最認同的系列，吃透它，不要疊加。這往往比兩個系列各用一半更有效率。

適合：對 AI 工作流還在摸索的開發者

四系列與 Hermes（你的 Agent）的相容性

系列 與 Hermes 的配合 注意事項
🔵 Agent Skills 良好 技能獨立，不會干擾 Hermes 的 session 管理
🟡 Superpowers 注意 session-start hook 可能與 Hermes 的啟動流程衝突，需測試
🟢 GStack 注意 Token 開銷高，Hermes 對話 session 要特別注意 context 用量
🔴 GSD Core 良好 .planning/ 目錄和 Hermes 的 workspace 完全獨立，無衝突

Step 4 / 5 · 情境推薦

~8 分鐘

按使用情境選系列

⚡ 快速原型 / Side Project / 一天內完成

推薦：🔵 Agent Skills（只用 /spec + /build auto）

  • 最輕量的結構化流程，Token 開銷最低
  • /build auto 一鍵從 spec 到實作
  • 不需要學習複雜的 phase 系統

🏢 個人全端產品 / 創辦人模式

推薦：🟢 GStack

  • /office-hours 幫你釐清產品方向再動工
  • /plan-ceo-review → /plan-design-review → /plan-eng-review 三線審查
  • /browse + /qa 做真實瀏覽器測試
  • 一個人有整個公司的感覺

📊 嚴肅的中大型專案 / 多週開發

推薦：🔴 GSD Core

  • .planning/ 目錄讓狀態跨 session 持久化
  • Fresh-context sub-agent 確保每步驟都在最佳狀態
  • 結構化的 Milestone → Phase → Task 管理
  • /gsd-autonomous 可以讓 AI 自主跑完整個 phase

🧪 重視程式碼品質 / TDD 文化

推薦：🟡 Superpowers（+ Agent Skills 補充）

  • SDD 自動化流程 + 嚴格 RED-GREEN-REFACTOR TDD
  • 技能自動觸發，不需手動選擇
  • 94% PR 拒絕率——真的很嚴格但品質最高
  • 搭配 Agent Skills 的 security/performance 技能作補充

🔧 現有 codebase 維護模式

推薦：🔵 Agent Skills

  • 完整的 review、security、performance、deprecation 技能
  • 不需要「新專案啟動」流程，直接按需使用個別技能
  • doubt-driven-development 對高風險修改特別有用
  • source-driven-development 適合需要查閱大量文件的維護工作

按開發者類型選系列

🌱 新手 Vibe Coder（剛開始用 AI 寫程式）

推薦路徑：

  1. 先不裝任何 skill pack，原生 Claude Code 用一週
  2. 裝 Agent Skills，跟著 /spec → /plan → /build → /test → /ship 走
  3. 感受到 AI 品質退化後，再研究 GSD Core 的 phase loop

理由：Agent Skills 最像教科書，每個技能都有清楚的 When to Use 和 Verification。

🚀 進階 Vibe Coder（已熟悉 AI 開發）

推薦組合：

  • 主力流程： GSD Core（context engineering 真的能解決長 session 品質問題）
  • 補充技能： Agent Skills 的 doubt-driven-development、source-driven-development
  • 工具增強： GStack 的 /browse（如果需要瀏覽器 QA）

👨‍💼 Indie Developer / 創辦人型開發者

推薦： GStack 作為主力，搭配 Agent Skills 的安全 + 效能技能。

GStack 的 /office-hours 和 CEO 視角審查讓你在動工前先確認方向，避免浪費時間做沒人要的功能。

Step 5 / 5 · 決策樹與入門包推薦

~5 分鐘

快速決策樹

Q1：你的主要痛點是什麼？

  • 「AI 越用越爛、長 session 品質退化」→ 🔴 GSD Core
  • 「程式碼品質差、不寫測試」→ 🟡 Superpowers
  • 「不知道產品方向對不對」→ 🟢 GStack
  • 「沒有系統化開發流程」→ 🔵 Agent Skills

Q2：你的專案規模？

  • 一天 side project → 🔵 Agent Skills
  • 一週 MVP → 🔵 Agent Skills 或 🟢 GStack
  • 一個月以上大型專案 → 🔴 GSD Core
  • 需要嚴格品質管控 → 🟡 Superpowers

Q3：你願意投入多少學習時間？

  • 想立刻用 → 🔵 Agent Skills（30 分鐘上手）
  • 願意花半天理解系統 → 🟡 Superpowers 或 🟢 GStack
  • 願意深入研究 → 🔴 GSD Core

總結

一句話定位 最適合誰
🔵 Agent Skills — 軟體工程百科 所有人的入門首選，中小專案主力
🟡 Superpowers — 開發方法論 最自動化、最強調 TDD、最有主見
🟢 GStack — 虛擬工程團隊 創辦人/獨立開發者，全端產品建構
🔴 GSD Core — 上下文工程框架 最解決根本問題、最適合大型長期專案

沒有「最好的」——只有「最適合你的」。建議從 Agent Skills 入門，遇到瓶頸後根據具體痛點選擇升級路徑。

Vibe Coding 實戰 · superpowers + Git

用 hermes + superpowers 走一輪完整的 AI 驅動開發流程，學會 git 基礎 + 每階段自動 commit，60–90 分鐘

前言

前言 · 什麼是 Vibe Coding？什麼是 Superpowers？

~5 分鐘

Vibe Coding 是什麼

Vibe Coding 是一種你主導方向、AI 執行實作的開發方式。你不需要一行一行寫程式——你描述你要什麼，AI agent 幫你寫。但「叫 AI 寫 code」跟「AI 寫出好 code」中間差很遠。大多數人第一次嘗試都遇到同樣的問題：AI 跳過設計直接亂寫、沒有測試、改到一半偏離需求。

Superpowers 是什麼

Superpowers 是一套給 coding agent 用的完整開發方法論，打包成一組 skills。它不是一個「能讓 AI 跑程式碼」的工具——hermes 本身就有 tool-use（shell、檔案讀寫等）。Superpowers 的價值是：自動在正確的時機觸發正確的工作流程，而且每個階段都會用 git commit 留下紀錄。

裝好之後，你只要說「幫我做一個 X」，superpowers 就會自動走過這些階段：

  1. Brainstorming——先問你需求、釐清設計，不會直接跳進寫 code
  2. Git Worktree——建立隔離的開發環境（一條新的 branch）
  3. Writing Plans——把設計拆成一個個 2~5 分鐘的小任務
  4. Subagent-Driven Development——每個任務派一個子 agent 執行，搭配 TDD（先寫測試再寫 code）
  5. Code Review——對照計畫逐項檢查
  6. Finishing——merge 或 PR，收尾

每個階段都會自動 commit——所以你回頭看 git log，就能看到整個開發歷程，一步一步清清楚楚。

  1. Step 1：在 hermes TUI 安裝 superpowers（用 URL 安裝）
  2. Step 2：建立專案資料夾 + 初始化 git

  4. Step 4：用 superpowers 走完開發流程——看每個階段怎麼自動 commit
  5. Step 5：收尾——回顧成果、下次預告

這堂課假設你已完成 Lesson 1（安裝 hermes），hermes 可以在你的機器上正常對話。不需要做過 Lesson 2–5。

本堂是實作課，hermes 在課堂中會幫你寫程式——需要付費 model（/model anthropic:claude-sonnet-4 或同等）。Superpowers 的 SDD 流程會派子 agent，免費 model 幾乎無法完成。

Step 1 / 5 · 安裝 superpowers

~5 分鐘

Superpowers 是一組遵循 agentskills.io 開放標準的 skills。hermes 的 TUI 內建了 Skills Hub，可以直接用 URL 安裝——不需要手動 clone。

在 hermes TUI 輸入安裝指令

打開 hermes TUI，輸入：

hermes 會從 GitHub 抓取 superpowers 的所有 skills，安裝到 ~/.hermes/skills/ 目錄下。

安裝完成後，你會擁有這些 skills：

  • writing-plans——把設計拆成可執行任務
  • executing-plans——照計畫一步步實作
  • subagent-driven-development——派子 agent + 兩階段 review
  • test-driven-development——TDD 循環
  • using-git-worktrees——隔離開發環境
  • requesting-code-review / receiving-code-review——code review 流程
  • finishing-a-development-branch——收尾 merge/PR
  • systematic-debugging——系統化除錯
  • verification-before-completion——完成前最終驗證

Step 2 / 5 · 建立專案資料夾 + 初始化 git

~5 分鐘

Superpowers 的核心流程需要 git——它會在每個開發階段自動 commit，幫你留下完整紀錄。所以在開始之前，我們先建好專案資料夾並初始化 git。

1. 建立專案資料夾

想一個你想做的小工具名稱。開一個 WSL 終端機（不是 hermes TUI），建立資料夾：

mkdir ~/my-first-project
cd ~/my-first-project

（把 my-first-project 換成你想要的名字，例如 csv-analyzer、todo-cli 等。）

2. 初始化 git

在專案資料夾裡：

git init

你會看到類似這樣的訊息：

Initialized empty Git repository in /home/你的名字/my-first-project/.git/

這代表 git 已經開始追蹤這個資料夾了。

3. 設定 git 的名字和 email（第一次用 git 才需要）

如果你從來沒設定過 git，它會在第一次 commit 時報錯。先設好：

git config --global user.name "你的名字"
git config --global user.email "你的email"

這只是 commit 紀錄上會顯示的名字，不需要是真實 email。

4. 確認 git 狀態

git status

應該看到：

On branch main
No commits yet
nothing to commit

空的、乾淨的——正是我們要的起點。

✓ 專案資料夾建好、git init 完成、git status 正常 → checkpoint 2 完成。

我卡住了

git init 說找不到 git

WSL Ubuntu 需要安裝 git：

sudo apt install git -y

branch 名稱是 master 不是 main

舊版 git 預設 branch 叫 master，不影響操作。想改成 main：

git branch -m master main

Step 3 / 5 · Git 是什麼？為什麼 Vibe Coding 需要它？

~5 分鐘（讀完就好，不用動手）

上一步你已經跑了 git init。在讓 superpowers 開始大展身手之前，花幾分鐘了解 git 在幹什麼——不用精通，知道三件事就夠了。

1. Git 是「版本控管」工具

想像你在寫一篇很長的報告。每寫完一段，你存一個版本：報告v1.docx、報告v2.docx、報告v3-最終版.docx、報告v3-最終版-真的最終.docx……

Git 做的就是這件事，但更聰明：

  • 它不需要你手動存不同檔案——每次「commit」就是一個存檔點
  • 每個存檔點都有一行訊息描述「這次改了什麼」
  • 你隨時可以回到任何一個存檔點
  • 它只存「改動」，不會佔一堆空間

2. 為什麼 Vibe Coding 特別需要 git

當 AI 幫你寫 code 時，它一次可能改動十幾個檔案。如果改壞了，沒有 git 你就只能從頭來過。有了 git：

  • 每個階段自動存檔——superpowers 會在 brainstorm 完、plan 完、每個任務實作完時自動 commit。壞了就回到上一個好的存檔點。
  • Branch（分支）= 安全的實驗空間——superpowers 會開一條新的 branch 來寫 code，主線（main）不受影響。滿意了再合併，不滿意就丟掉。
  • 看得到 AI 做了什麼——git log 列出每一步的 commit 訊息，git diff 看改了哪些行。AI 不再是黑箱。

3. 你只需要記住這幾個指令

Superpowers 會自動幫你 commit，你不太需要手動操作。但知道怎麼「看」很重要：

指令 作用
git status看目前有哪些檔案被改了
git log --oneline看所有 commit 的一行摘要
git diff看目前還沒 commit 的改動
git branch看目前有哪些 branch

接下來 Step 4 跑完 superpowers 之後，你會用 git log --oneline 親眼看到每個階段的 commit——那時候這些指令就會變得很具體。

想學更多 git？

這堂課只教 git 最核心的概念，夠你配合 superpowers 使用。如果想深入學：

  • Pro Git（繁體中文版）——免費線上教材，從基礎到進階都有
  • GitHub 的 Getting Started with Git——簡短、實用

Step 4 / 5 · Superpowers 各階段 + 自動 commit

~40 分鐘（★ 主場——看 superpowers 驅動整個開發流程）

現在 superpowers 裝好了、git 也初始化了。打開 hermes TUI，cd 到你的專案資料夾，然後告訴 hermes 你想做什麼。Superpowers 會自動驅動整個開發流程，每個階段都會留下 commit。

0. 進入專案目錄、開新對話

在 hermes TUI 裡：

/new

重開一個新對話讓 superpowers 的 bootstrap 生效。然後確認你在專案目錄裡（hermes 有 shell 工具，它可以 cd）。

1. 說出你想做的東西

挑一個你真的想要的小工具（不要太大，30~60 分鐘的實作量）。直接跟 hermes 說：

幫我在這個資料夾做一個 [描述你的工具]

例如：

  • 「幫我做一個 CLI 工具，讀取一個 CSV 檔案，算出每欄的平均值和最大值」
  • 「幫我做一個 Python 腳本，把一個資料夾裡所有圖片轉成 webp 格式」
  • 「幫我做一個簡單的 todo list 網頁，可以新增和刪除待辦事項」
第一次建議選「你知道輸入長什麼樣」的工具。能說清楚「輸入是 X，我要 Y」，superpowers 的 brainstorming 會更有效率。

階段 A：Brainstorming（自動觸發）

using-superpowers 這個 bootstrap skill 會在對話開始時自動載入。當你說「幫我做一個 X」，它不會直接寫 code——而是觸發 brainstorming skill：

  • 提問——問你需求上模糊的地方（「輸入如果有空行怎麼辦？」「要支援哪些格式？」）
  • 探索替代方案——「用 pandas 還是純 Python？」
  • 分段呈現設計——不會一次丟一大塊，而是短到你真的會看完的段落

你的工作就是看它的問題、給明確答案。不確定的地方講「你決定」也行。Brainstorm 結束時，hermes 會呈現一份完整設計摘要——你說「好，按這個做」就進入下一階段。

階段 B：Git Worktree（自動觸發）

設計確認後，superpowers 的 using-git-worktrees skill 會自動建立一個 git worktree——在一條新的 branch 上工作，不會弄髒你的 main branch。

你會在終端看到類似：

Switched to a new branch 'feature/csv-analyzer'

這就是 Step 3 說的「branch = 安全的實驗空間」——所有接下來的開發都在這條 branch 上進行。

階段 C：Writing Plans（自動觸發）

writing-plans skill 會把設計拆成具體的任務清單：

  • 每個任務 2~5 分鐘可完成
  • 每個任務附上確切的檔案路徑、程式碼範圍、驗證步驟
  • 計畫會呈現給你看——確認後才開始實作

階段 D：Subagent-Driven Development + TDD（自動觸發）

這是 superpowers 最強大的部分。subagent-driven-development skill 會：

  1. 對每個任務派一個子 agent——子 agent 只專注於這個任務
  2. TDD 循環——先寫一個會 fail 的測試（RED），再寫實作讓它通過（GREEN），最後重構（REFACTOR）
  3. 每完成一個 RED-GREEN-REFACTOR 循環就 commit——你的 git log 會看到一步一步的進度
  4. 兩階段自動 review——第一階段檢查「有沒有按規格做」，第二階段檢查「程式碼品質」
  5. 繼續下一個任務——直到計畫裡所有任務完成

這個過程可能需要 10~30 分鐘。你主要是看它跑，在關鍵節點確認。

實作過程提醒
  • 別急著打斷：SDD 設計上就是讓 agent 自主跑完一連串任務。中途打斷會讓上下文混亂
  • 有 error 不等於失敗：TDD 的 RED 階段本來就會有 test failure——那是正常的。等它自己修到 GREEN
  • 真的卡住才介入：如果同一個 error 反覆出現超過 3 次，才需要你說「試試另一個方向」

階段 E：Code Review（自動觸發）

SDD 跑完後，requesting-code-review skill 會自動啟動最終 review：

  • Critical——必須修，會擋住進度
  • Major——強烈建議修
  • Minor——改了更好，不改也行

如果有 Critical issue，hermes 會自動修正然後重新 review。修完也會 commit。

看看 git log

Superpowers 跑完後，回到 WSL 終端機，在專案目錄裡跑：

git log --oneline

你會看到一連串 commit——每一行就是開發過程中的一步。從最早的設計到最後的 review，superpowers 幫你留下了完整的開發歷程。

也可以看更詳細的版本：

git log --oneline --graph --all

這會顯示 branch 的分支圖——你的 feature branch 從 main 分出去的樣子一目了然。

✓ Superpowers 跑完整輪、git log 看到各階段的 commit → checkpoint 3 完成。

我卡住了

hermes 沒跑 brainstorming、直接開始寫 code

  1. 傳 /new 重開對話——superpowers 的 bootstrap 是在對話開始時觸發的
  2. 確認 /skills 列表有 using-superpowers
  3. 如果用免費 model，它可能推理力不足以遵循 skill 指令——請切換到付費 model（/model anthropic:claude-sonnet-4）

hermes 沒有自動派子 agent

SDD 需要 model 支援子 agent 功能。確認你用的是付費 model。免費 model 不支援子 agent dispatch。

子 agent 一直 fail

先看 review 結果——如果是「規格不符」，可能是 brainstorming 的設計不夠清楚。直接說：「這個任務的需求其實是 [更清楚的描述]，重跑這個任務。」

跑太久 / 無限迴圈

在 hermes TUI 按 Ctrl+C 中斷，然後說：「跳過這個任務，先做下一個。」

git log 沒看到 commit

確認你在正確的 branch 上。跑 git branch 看看——superpowers 可能在 feature branch 上工作。切換過去：

git branch
git checkout feature/你的分支名

然後再跑 git log --oneline。

Step 5 / 5 · 收尾

~5 分鐘

恭喜，3 個 checkpoints 全部完成：

  1. ✓ Superpowers 安裝成功、/skills 列表看得到
  2. ✓ 專案資料夾建好、git init 完成
  3. ✓ Superpowers 跑完整輪、git log 看到各階段的 commit

Finishing：merge 或 PR

Superpowers 的 finishing-a-development-branch skill 會在最後呈現選項：

  1. Merge——把 feature branch 合併到 main
  2. PR——開一個 Pull Request（需要 remote repo）
  3. Discard——丟棄這次實作

第一次做，直接選 merge 就好。hermes 會幫你處理 git 操作。

回顧：你剛剛走過的完整流程

Brainstorming → Git Worktree → Writing Plans → SDD + TDD（自動實作 + 自動 commit）→ Code Review → Finishing

這就是 superpowers 帶來的 Vibe Coding 流程。你只需要在關鍵節點做決定（確認設計、確認計畫、確認 merge），其餘交給 skills 自動驅動。而 git 忠實記錄了每一步——你隨時可以回頭看、回頭改。

加碼 A · 用 superpowers 除錯

之後程式出了 bug，不要直接叫 hermes 修——讓它觸發 systematic-debugging skill。Superpowers 的除錯流程是 4 階段 root cause analysis：先重現、再縮小範圍、找到根因、最後修。比「你修一下」精確得多。

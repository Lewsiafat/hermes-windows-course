前言

前言 · 為什麼要比較這四個系列？

~5 分鐘

Claude Code 的 Skill 系統讓你可以「預裝」一套工作流程或最佳實踐，讓 AI agent 在每個 session 都照著來。但問題是——哪個系列適合你？

這次要比較的四個都屬於「Pre-Plan Skill」——在你開始工作之前就改變 agent 行為的系統級技能包，彼此定位不同但常被混淆：

garrytan/gstack

🔴 GSD Core

open-gsd/gsd-core

學完這份指南你能做到什麼

  1. 能說出每個系列的核心定位（一句話）

🔵 Agent Skills — 軟體工程最佳實踐百科

Addy Osmani 把資深工程師的工作流程編碼為「流程，而非文章」。最大特色是每個技能都附有「反合理化表」——讓 AI 無法用藉口跳過步驟。

技能按開發流程分類：

8 個 slash 指令：/spec → /plan → /build → /test → /review → /ship

🟡 Superpowers — Sub-agent 驅動開發方法論

不只是技能，而是一套完整的開發哲學。核心是 SDD（Sub-agent Driven Development）：agent 先規劃再執行，所有重型工作分派給 sub-agent，能自主運行數小時而不偏離。

subagent-driven-developmenttest-driven-development brainstormingwriting-plans executing-plansdispatching-parallel-agents using-git-worktreessystematic-debugging …共 14 個

✨ 特色：技能自動觸發，不需手動呼叫 slash 指令。雙階段審查（規格合規 + 程式碼品質）。

🟢 GStack — 虛擬工程團隊

Garry Tan 的核心信念：「在 AI 時代完整實作的邊際成本趨近於零」。58 個技能涵蓋 CEO 審查、設計諮詢、Playwright QA、安全審計到部署監控。

/office-hours/plan-ceo-review /plan-design-review/design-shotgun /qa/browse /cso/land-and-deploy /canary…共 58 個

✨ 特色：/office-hours YC 風格的創業診斷、內建 Playwright 瀏覽器 QA、多 AI 交叉驗證。

🔴 GSD Core — 上下文工程框架

解決 AI 最根本的問題：長 session 品質退化（context rot）。所有重型工作都在全新 200K token 上下文的 sub-agent 中執行，並透過 .planning/ 目錄（STATE.md、ROADMAP.md 等）跨 session 持久化狀態。

/gsd-new-project/gsd-spec-phase /gsd-plan-phase/gsd-execute-phase /gsd-verify-work/gsd-ship /gsd-autonomous/gsd-mempalace-capture …共 69 指令 + 34 agent

✨ 特色：兩階段命名空間路由（6 個路由 → 69 個指令）讓 idle token 成本極低（~120 tokens）。

獨家特色說明

🔵 Agent Skills 獨有：反合理化表（Anti-rationalization tables）

每個技能都明確列出「AI 可能給的藉口」和「為什麼這些藉口不成立」。防止 Claude 以「這個步驟太慢」或「這個情況不需要測試」等理由跳過重要流程。

🟡 Superpowers 獨有：SDD 雙階段審查

Sub-agent 完成後，不是直接合併，而是先做「規格合規審查」再做「程式碼品質審查」。這也是 PR 拒絕率高達 94% 的原因——真的很嚴格。

🟢 GStack 獨有：YC Office Hours (/office-hours)

模擬 Y Combinator 辦公時間的創業診斷對話。AI 會扮演 YC 合夥人，問「這個功能真的有人要付錢嗎？」、「你的增長飛輪是什麼？」。適合在動工前先釐清產品方向。

🔴 GSD Core 獨有：MemPalace 記憶宮殿

/gsd-mempalace-capture 讓 agent 把重要的技術決策、架構洞見存入結構化的記憶檔案，之後用 /gsd-mempalace-recall 跨 session 調出。可以跨好幾個月的專案維持上下文連貫性。

Step 3 / 5 · 衝突分析與組合建議

~8 分鐘

⚠️ 衝突組合（不要同時裝）

❌ Superpowers + GSD Core

兩者都有完整的「規劃 → 執行 → 驗證」流程，且都會 hook 到 session start。同時啟用，AI 不知道該遵循哪個方法論，行為不可預測。

❌ Superpowers + GStack

兩者都試圖控制整個開發流程，啟動機制可能互相干擾。GStack 的虛擬團隊角色和 Superpowers 的 SDD 流程設計理念根本不同。

❌ 任意三個以上全裝

絕對不要。Token 爆炸、流程衝突、AI 行為完全不可預測。只裝一個主系列，最多搭配一個輔助。

✅ 可以疊加的組合

✅ Agent Skills + GSD Core

最自然的組合。Agent Skills 作為個別技能參考（security、performance、doubt-driven-development），GSD Core 作為工作流骨架。兩者設計理念互補，衝突極低。

推薦給：中大型專案的進階 Vibe Coder

✅ Agent Skills + GStack 部分技能

只安裝 GStack 的工具性技能（/browse、/qa、/cso），搭配 Agent Skills 的完整開發流程。需要注意 CLAUDE.md 的合併方式。

推薦給：需要瀏覽器 QA 的全端開發者

✅ 單一系列全用（最乾淨）

選一個你最認同的系列，吃透它，不要疊加。這往往比兩個系列各用一半更有效率。

適合：對 AI 工作流還在摸索的開發者

四系列與 Hermes（你的 Agent）的相容性

系列 與 Hermes 的配合 注意事項
🔵 Agent Skills 良好 技能獨立，不會干擾 Hermes 的 session 管理
🟡 Superpowers 注意 session-start hook 可能與 Hermes 的啟動流程衝突，需測試
🟢 GStack 注意 Token 開銷高，Hermes 對話 session 要特別注意 context 用量
🔴 GSD Core 良好 .planning/ 目錄和 Hermes 的 workspace 完全獨立，無衝突

Step 4 / 5 · 情境推薦

~8 分鐘

按使用情境選系列

⚡ 快速原型 / Side Project / 一天內完成

推薦：🔵 Agent Skills（只用 /spec + /build auto）

  • 最輕量的結構化流程，Token 開銷最低
  • /build auto 一鍵從 spec 到實作
  • 不需要學習複雜的 phase 系統

🏢 個人全端產品 / 創辦人模式

推薦：🟢 GStack

  • /office-hours 幫你釐清產品方向再動工
  • /plan-ceo-review → /plan-design-review → /plan-eng-review 三線審查
  • /browse + /qa 做真實瀏覽器測試
  • 一個人有整個公司的感覺

📊 嚴肅的中大型專案 / 多週開發

推薦：🔴 GSD Core

  • .planning/ 目錄讓狀態跨 session 持久化
  • Fresh-context sub-agent 確保每步驟都在最佳狀態
  • 結構化的 Milestone → Phase → Task 管理
  • /gsd-autonomous 可以讓 AI 自主跑完整個 phase

🧪 重視程式碼品質 / TDD 文化

推薦：🟡 Superpowers（+ Agent Skills 補充）

  • SDD 自動化流程 + 嚴格 RED-GREEN-REFACTOR TDD
  • 技能自動觸發，不需手動選擇
  • 94% PR 拒絕率——真的很嚴格但品質最高
  • 搭配 Agent Skills 的 security/performance 技能作補充

🔧 現有 codebase 維護模式

推薦：🔵 Agent Skills

  • 完整的 review、security、performance、deprecation 技能
  • 不需要「新專案啟動」流程，直接按需使用個別技能
  • doubt-driven-development 對高風險修改特別有用
  • source-driven-development 適合需要查閱大量文件的維護工作

按開發者類型選系列

🌱 新手 Vibe Coder（剛開始用 AI 寫程式）

推薦路徑：

  1. 先不裝任何 skill pack，原生 Claude Code 用一週
  2. 裝 Agent Skills，跟著 /spec → /plan → /build → /test → /ship 走
  3. 感受到 AI 品質退化後，再研究 GSD Core 的 phase loop

理由：Agent Skills 最像教科書，每個技能都有清楚的 When to Use 和 Verification。

🚀 進階 Vibe Coder（已熟悉 AI 開發）

推薦組合：

  • 主力流程： GSD Core（context engineering 真的能解決長 session 品質問題）
  • 補充技能： Agent Skills 的 doubt-driven-development、source-driven-development
  • 工具增強： GStack 的 /browse（如果需要瀏覽器 QA）

👨‍💼 Indie Developer / 創辦人型開發者

推薦： GStack 作為主力，搭配 Agent Skills 的安全 + 效能技能。

GStack 的 /office-hours 和 CEO 視角審查讓你在動工前先確認方向，避免浪費時間做沒人要的功能。

Step 5 / 5 · 決策樹與入門包推薦

~5 分鐘

快速決策樹

Q1：你的主要痛點是什麼？

  • 「AI 越用越爛、長 session 品質退化」→ 🔴 GSD Core
  • 「程式碼品質差、不寫測試」→ 🟡 Superpowers
  • 「不知道產品方向對不對」→ 🟢 GStack
  • 「沒有系統化開發流程」→ 🔵 Agent Skills

Q2：你的專案規模？

  • 一天 side project → 🔵 Agent Skills
  • 一週 MVP → 🔵 Agent Skills 或 🟢 GStack
  • 一個月以上大型專案 → 🔴 GSD Core
  • 需要嚴格品質管控 → 🟡 Superpowers

Q3：你願意投入多少學習時間？

  • 想立刻用 → 🔵 Agent Skills（30 分鐘上手）
  • 願意花半天理解系統 → 🟡 Superpowers 或 🟢 GStack
  • 願意深入研究 → 🔴 GSD Core

總結

一句話定位 最適合誰
🔵 Agent Skills — 軟體工程百科 所有人的入門首選，中小專案主力

一、各系列摘要

1. 🔵 Agent Skills（addyosmani/agent-skills）

開發者： Addy Osmani（前 Google Chrome 工程總監、知名前端效能專家）

核心哲學： 將資深工程師的最佳實踐編碼為「流程而非文章」（Process, not prose），讓 AI agent 能夠一致性地遵循軟體工程全生命週期的品質標準。每個技能都包含反合理化表（Anti-rationalization tables），防止 AI 跳過步驟時自圓其說。

技能數量： 24 個技能 + 8 個 slash command + 4 個 agent persona + 7 份參考清單

技能清單（按階段）：

  • Define： interview-me、idea-refine、spec-driven-development
  • Plan： planning-and-task-breakdown
  • Build： incremental-implementation、test-driven-development、context-engineering、source-driven-development、doubt-driven-development、frontend-ui-engineering、api-and-interface-design
  • Verify： browser-testing-with-devtools、debugging-and-error-recovery
  • Review： code-review-and-quality、code-simplification、security-and-hardening、performance-optimization
  • Ship： git-workflow-and-versioning、ci-cd-and-automation、deprecation-and-migration、documentation-and-adrs、observability-and-instrumentation、shipping-and-launch

Slash 指令： /spec、/plan、/build、/build auto、/test、/review、/webperf、/code-simplify、/ship

優點：

  • 覆蓋面最完整，從構想到上線 24 個技能涵蓋全生命週期
  • 「反合理化」機制獨特，防止 AI 偷懶
  • 漸進式資訊揭露（Progressive disclosure），只在需要時載入參考文件
  • 跨平台支援最廣（Claude Code、Cursor、Gemini CLI、Windsurf、OpenCode、Copilot、Kiro）
  • 單個 SKILL.md 約 8-15KB，token 開銷適中

缺點：

  • 偏重「檢查清單」風格，對 vibe coding 場景可能過於嚴謹
  • 缺少 sub-agent 驅動開發等進階自動化流程
  • 沒有專案狀態管理機制（無 STATE.md 等持久化記憶）

Token 開銷： 中等。單技能 8-15KB（約 2k-4k tokens），因為漸進式載入，實際每次對話只會啟用相關技能。

2. 🟡 Superpowers（obra/Superpowers）

開發者： Jesse Vincent / Prime Radiant Inc.（知名開源開發者，RT/Perl 等專案的創建者）

核心哲學： 完整的軟體開發方法論，而非單純的技能集合。強調「agent 不該直接寫程式，而是先規劃再執行」。以 Sub-agent Driven Development（SDD）為核心，讓 AI 能自主運行數小時而不偏離計畫。特別重視 TDD 和 YAGNI 原則。

技能數量： 14 個技能（精簡但完整的流程鏈）

技能清單：

  • 測試： test-driven-development（RED-GREEN-REFACTOR 循環）
  • 除錯： systematic-debugging（四階段根因分析）、verification-before-completion
  • 協作： brainstorming、writing-plans、executing-plans、dispatching-parallel-agents、requesting-code-review、receiving-code-review、using-git-worktrees、finishing-a-development-branch、subagent-driven-development
  • Meta： writing-skills、using-superpowers

優點：

  • SDD 是最成熟的 sub-agent 自動化流程
  • 自動觸發機制——技能不需手動呼叫，agent 根據情境自動啟用
  • 雙階段審查（規格合規 + 程式碼品質）確保產出品質
  • 嚴格的 PR 審查文化（94% PR 拒絕率）
  • brainstorming 技能有視覺化伴侶功能（HTML 即時預覽）
  • 零依賴設計

缺點：

  • 技能數量少（14 個），缺少安全審計、效能優化等專項技能
  • 學習曲線較陡，方法論驅動而非指令驅動
  • 不接受社區新增技能，擴展性受限
  • 缺少專案級狀態管理

Token 開銷： 中等偏高。核心 SKILL.md 單檔約 10-22KB（subagent-driven-development 達 21KB）。

3. 🟢 GStack（garrytan/gstack）

開發者： Garry Tan（Y Combinator 總裁兼 CEO、前 Palantir 工程師、Posterous 共同創辦人）

核心哲學： 「一個人配合 AI 能做到二十人團隊的產出」。將 Claude Code 打造為虛擬工程團隊——包含 CEO 審查者、工程經理、設計師、QA 主管、安全官員、發布工程師等角色。核心信念是「Boil the Ocean」——在 AI 時代完整實作的邊際成本趨近於零。

技能數量： 58 個 SKILL.md（含 iOS 系列、OpenClaw 系列、瀏覽器技能等）

主要 Slash 指令：

  • 規劃審查： /office-hours、/plan-ceo-review、/plan-eng-review、/plan-design-review、/plan-devex-review
  • 設計： /design-consultation、/design-shotgun、/design-html、/design-review
  • QA： /qa、/qa-only、/review、/cso（OWASP + STRIDE）
  • 交付： /ship、/land-and-deploy、/canary、/benchmark
  • 工具： /browse（Playwright）、/investigate、/codex（OpenAI 第二意見）、/autoplan、/retro
  • 狀態管理： /context-save、/context-restore、/learn、/freeze、/guard

優點：

  • 技能數量最多（58 個），覆蓋從產品策略到安全審計
  • /office-hours 是獨一無二的創業診斷工具
  • 內建 Playwright 瀏覽器（/browse）可做真實 QA
  • 多 AI 交叉驗證（/codex 調用 OpenAI 做第二意見）
  • /autoplan 自動化管線（CEO 審查 → 設計審查 → 工程審查）
  • iOS 專用技能系列（/ios-qa、/ios-design-review、/ios-fix）
  • ETHOS.md 注入每個技能的 preamble，確保一致的建構哲學

缺點：

  • 主 SKILL.md 達 50KB（約 12k tokens），token 開銷高
  • 安裝需要 Bun + Git clone，不如 plugin marketplace 便利
  • Garry Tan 個人色彩極強，不一定適合所有開發者
  • 160KB token ceiling 警告存在，大型技能可能觸發

Token 開銷： 高。主 SKILL.md 約 50KB（~12k tokens），prompt caching 可緩解成本，但注意力預算（attention budget）仍是問題。

4. 🔴 GSD Core（open-gsd/gsd-core）

開發者： 社區驅動的開源專案

核心哲學： 「Context Engineering（上下文工程）」——解決 AI 在長對話中品質退化（context rot）的根本問題。透過在全新上下文的 sub-agent 中執行所有重度工作，保持主 session 精簡。五步驟 phase loop（Discuss → Plan → Execute → Verify → Ship）配合檔案系統狀態管理（.planning/）。

指令數量： 69 個 commands + 34 個 agent 定義 + 多層 workflow

六大命名空間路由：

  • 核心工作流： /gsd-new-project、/gsd-spec-phase、/gsd-plan-phase、/gsd-execute-phase、/gsd-verify-work、/gsd-ship、/gsd-autonomous
  • 品質門控： /gsd-code-review、/gsd-debug、/gsd-secure-phase、/gsd-eval-review、/gsd-ui-review
  • 上下文智慧： /gsd-map-codebase、/gsd-mempalace-capture、/gsd-mempalace-recall、/gsd-extract-learnings
  • 專案管理： /gsd-workspace、/gsd-workstreams、/gsd-progress、/gsd-stats

34 個 Agent 定義（部分）： gsd-planner、gsd-executor、gsd-code-reviewer、gsd-debugger、gsd-security-auditor、gsd-verifier、gsd-domain-researcher、gsd-codebase-mapper、gsd-mempalace-curator 等

優點：

  • 上下文工程理論最成熟，從根本解決 context rot 問題
  • 每個 sub-agent 啟動時有全新的 200K token 上下文
  • .planning/ 目錄：STATE.md、CONTEXT.md、ROADMAP.md、PLAN.md 等人類可讀的持久化狀態
  • 兩階段層級路由讓 eager listing 成本極低（~120 tokens vs ~2,150）
  • effort: max / effort: low 精細化 token 預算控制
  • npx 一鍵安裝
  • Edge coverage probe 和 Prohibition coverage 等深度規格分析

缺點：

  • 學習曲線最陡，概念和指令數量龐大
  • 對小專案或快速原型過於 heavyweight
  • 命名慣例冗長（所有指令以 /gsd- 開頭）
  • 社區生態尚在發展中

Token 開銷： 中低到高（取決於使用模式）。命名空間路由設計讓 idle 成本極低，但執行重度 workflow 時 orchestrator + agent 各自消耗大量 token。

三、Vibe Coding 選用建議摘要

  • 快速原型 / Side Project → Agent Skills（/build auto）
  • 個人全端產品 / 創辦人模式 → GStack（/office-hours + 三線審查）
  • 嚴肅中大型專案 / 多週開發 → GSD Core（.planning/ 跨 session 狀態）
  • 重視程式碼品質 / TDD → Superpowers + Agent Skills 補充
  • 現有 codebase 維護 → Agent Skills（doubt-driven-development）

衝突組合（不要同時裝）

  • ❌ Superpowers + GSD Core（都搶 session hook）
  • ❌ Superpowers + GStack（都試圖控制整個流程）
  • ❌ 任意三個以上全裝（Token 爆炸）

可疊加組合

  • ✅ Agent Skills + GSD Core（百科 + 流程框架，互補）
  • ✅ Agent Skills + GStack 部分工具（/browse、/qa、/cso）

沒有「最好的」——只有「最適合你的」。建議從 Agent Skills 入門，遇到瓶頸後根據具體痛點選擇升級路徑。
